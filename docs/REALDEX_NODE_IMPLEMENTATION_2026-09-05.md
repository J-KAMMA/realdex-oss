# RealDEX — 分散ノード・交換最適化の実装レポート

**2026-09-05 / Node Preview 0.3.0-dev.20260905**

## 目的と今回の到達点

依頼は「最終的にすべてのチェーンとトークンでスワップとブリッジを行えるDEX」「自分のコンピュータをサーバーとして接続」「Factoryからプール作成」「最適な交換」である。

今回は添付`realdexbasesepolia5885d029020b.zip`を基準に、個人PCで実行できるノード、署名付きFactory候補の中継、費用控除後の経路比較、離散分割の最適化を追加した。**ノードによる発見と、チェーン上の資産移動を明確に分離した開発版**であり、全チェーン・全トークンの実取引完成版ではない。

コードの変更は追加`node/`、追加文書、ルートREADMEの案内・誤記訂正である。既存コントラクト、元の署名・復旧処理、依存関係とロックファイルは変更していない。元のデプロイ確認ゲートを外していない。今回、デプロイ、ウォレット接続、資産移動、LP投入、外部公開は行っていない。

## 設計として変えたこと

### 1. PCノードを資金の保管場所にしない

個人PCは候補発見と配信を担う。残高・LP持分・交換結果の正本は各チェーンとその実行プロトコルに残す。ノード同士で独自の残高台帳を作らず、独自チェーンや管理者鍵も追加しない。

今回のノードはEd25519署名付き候補情報だけを配信し、ウォレット鍵、ユーザーのシード、資金、取引の署名APIを持たない。ブラウザが実行する取引は従来どおり利用者のウォレットによって署名する。ノード鍵は情報発信者の識別用であり、資金署名権ではない。

```text
個人PC A ←→ 個人PC B ←→ 個人PC C
       署名付きFactory候補の発見・中継
                         ↓
利用者のローカル検証器・経路計算器
  候補 → チェーン上の検証 → 見積り → 費用比較
                         ↓
              利用者のウォレットで明示署名
                         ↓
          各チェーンのFactory / Pool / Router
                         ↓
        必要な場合だけ、対応するBridge adapter
```

この図全体は目標構造である。今回つないだのはPC間の発見部分と独立した計算モジュールまでで、候補を既存実行画面へ自動昇格させる経路はまだない。

### 2. 「全トークン」を名前でまとめない

資産は`chain_id / asset_namespace:asset_reference`で識別する。たとえば同じ「USDC」という表示名でも、チェーン、発行元、ラップ経路が違えば別の資産として管理する。CAIP-19はこの区別の基盤であり、名前の一致を資産の同一性に使わない。[1]

「全チェーン」は追加アダプターで対応範囲を増やせる構造を意味する。各チェーンの実行方式、署名、最終確定、資産の移転規則まで同一だとは仮定しない。非譲渡トークン、売却停止、送信制限、税付き送金などを通常ERC-20として無条件に通さない。経路・流動性・検証手段がない場合は、対応不可の理由を表示する。

### 3. Factoryは公開参加を維持する

元の`LocalSwapFactory`はownerなし、トークンペアと手数料率を含むCREATE2でプールを作成する。ペア単位で一つではなく、**ペア×手数料率ごとに一つ**である。手数料はプール作成時に固定され、既存Poolの範囲は1〜100 bps。プロトコル手数料や後から変更する管理者を追加していない。

同じ構造をそのまま他のVMへ移せるとは扱わない。EVMではFactoryコントラクト、他の実行環境では当該チェーンのプログラム／モジュール／スクリプトによる同等機能を個別に検証する設計とする。既存の他DEXも検証済み経路として取り込み、自前プールだけに候補を限定しない方針を次段階に記録した。

### 4. 最大の表示受取額ではなく、追加費用控除後を選ぶ

新しい比較器は次を目的関数にする。

`score(route) = minimumOut(route) - additionalCostsConvertedToOutputAsset(route)`

`minimumOut`に含まれるLP手数料やブリッジ控除はもう一度引かない。承認・送信・受取側・リレイヤーなど追加費用だけを換算する。不明費用は0ではなく比較未完了とする。異なる入力額・受取資産・要求ID、期限切れ、許可しないリスク区分、未追跡の最終確定などは候補から除く。

経路選択に分割とガスコストを含める考え方は、Uniswapの公開Smart Order Routerにも見られる。[2] 今回はそのコードを流用せず、独立した整数比較と動的計画法を記述した。

比較器は渡された価格比の署名・操作耐性・実測精度を保証しない。`minimumOut`も指定条件下の取引制約であり、資産受取の無条件保証ではない。前後のシミュレーション、承認範囲、アカウント・受取人・セッションの束縛は引き続き必要である。

### 5. スワップとブリッジを同じ原子取引だと扱わない

同一チェーン上のRouter内処理と、チェーン間で最終確定を待つ転送は別の状態機械にする。ブリッジ方式ごとに対応チェーン・資産・最終確定・証明／アテステーション・復旧手順を記録する。CCTPも方式・チェーンごとの確定条件を持つため、「送信トランザクションが見えた」だけで受取完了としない。[3]

次のような複数段の経路では途中状態を記録し、受取側スワップに失敗しても自動的に送り元へ巻き戻せると表示しない。

```text
Chain AのToken X → A上の転送可能資産
                 → Bridge確定待ち
                 → Chain Bの転送先資産
                 → B上のToken Y
```

現在の追加ノードにブリッジ検証者・アテスター・新規クロスチェーン実行機能はない。元のブリッジアダプターと設計ゲートは維持したままである。

## 追加した実装

| 実装 | 内容 | 今回の境界 |
|---|---|---|
| `node/cli.mjs` | 初期化、公開鍵表示、起動、停止、外部待受の明示フラグ | ノード鍵だけを生成。資金鍵を扱わない |
| `lib/protocol.mjs` | 厳格な型・上限、正規化JSON、Ed25519、nonceに束縛した応答 | 発信者の真正性であって内容の正しさではない |
| `lib/store.mjs` | 永続改訂番号、内容指紋、巻き戻し・同一改訂の改変拒否、排他起動 | 全世界の合意ではない。設定した情報源だけ |
| `lib/transport.mjs` | HTTPS／loopback限定、非リダイレクト、期限・サイズ上限 | 自動発見、NAT越え、通信匿名化なし |
| `lib/server.mjs` | 情報の受理と中継、失効、読み取り専用API、ローカル画面配信 | 自動RPC選択・資金署名・送金なし |
| `optimizer/quote-objective.mjs` | 実質受取額ランキング、不明費用の分離 | 元の本番UIへは未接続 |
| `optimizer/discrete-split.mjs` | 有限候補の離散分割最適化 | 分割Router・実取引送信なし |
| `public/` | 日本語ノードコンソール、固定データの計算デモ | ウォレット接続ボタンなし |

## 分割最適化の意味

入力額を`N`個の等しい刻みに分ける。経路数を`R`、最大分割数を`S`とし、経路ごとに`k`刻みを割り当てた場合の最低出力と追加費用を入力する。動的計画法の状態を「使用した経路集合の先頭部分・割当済み刻み・使用分割数」とし、各経路に割り当てる刻み数を全て試す。

状態遷移は概ね`O(R × N² × S)`。今回の上限はR=8、N=128、S=4。配列は有界で、金額はBigInt。経路曲線の凹性を仮定しない。

最適性の対象は**入力した有限グリッド**であり、その外の経路・他の刻み・未知の流動性・将来ブロック・未知のガス価格を含まない。経路が同じプールを共有すると見積りが相互依存するため、今回はその組合せを拒否する。表示したプールIDが本当に異なるかは、呼び出し側のオンチェーン検証が必要である。

固定した架空の2プールでは、入力100,000最小単位を49,000／51,000に配分し、最低出力合計95,079から経路別追加費用200と共通実行費用25を引いた94,854を返した。これは動作例で、実際の市場価格・利益・性能改善率ではない。

## 実行した試験

2026-09-05時点の追加試験は**104件成功、失敗0、skip 0**。別に元のリリース計画試験**6件成功**。ログは`node/evidence/`に保存している。

確認対象は、署名改変、キー不一致、nonce不一致、期限、古い改訂、同一改訂での異なる内容、永続head、情報源の固定、中継元署名の保存、A→B→CのHTTP通信、中継ノード停止、期限切れ候補除去、Host／Origin制限、情報漏出防止、HTTP上限、起動競合、SIGTERM停止と再起動、比較条件と費用換算などである。

分割計算は、単一の試験項目内で**80個のseed付き小規模ケースを独立した総当たり実装と比較**し一致した。これは全入力に対する形式証明ではない。実装の状態遷移と有限探索範囲はソースに明示した。

TypeScript 5.8.3で、追加`.d.mts`の型利用例を`--strict --noEmit`で確認した。ルートのアプリ全体の型検査ではない。

Chromium 144による幅1280／390／320pxとCSS zoom 200%の**オフラインDOM描画試験**では、横方向のはみ出しなし、JS例外なし、ウォレット参照なし、計算結果94,854、状態取得失敗時の候補表示除去を確認した。画面画像を同梱した。

**ブラウザHTTP結合試験は未完了**。環境の管理ポリシーで`ERR_BLOCKED_BY_ADMINISTRATOR`となったため、ポリシーを変更せず、ローカルHTML/CSS/JSと注入した状態データによるDOM試験へ分離した。Nodeによる実HTTP試験が通ったことと、実ブラウザのHTTP動作・CSP適合は同一の証拠として扱わない。

### 実施していないこと

元のReact／Hardhat全体のビルド・全テストは、依存関係が未導入で、パッケージレジストリへのDNS解決もできない環境のため今回再実行していない。元ZIP内の過去の証拠を今回の成功件数に算入していない。Windows実機、複数物理PC、HTTPS終端、NAT、負荷耐性、本番ネットワーク、実トークン、ブリッジ決済も未確認である。

## 分散性と脅威モデル

同じ実装を複数PCに配置し、接続先と公開鍵を各運用者が決められる。特定の中央サーバーをこの発見ネットワークの必須要素にはしていない。ただし今回の実装は**明示的な接続先と情報源の固定を使う小規模メッシュ**で、公開DHTや無許可のグローバル発見網は未実装である。

家庭内PCはNATやファイアウォールの背後にあることが多く、一般的なP2P接続には到達性確認・リレー・hole punching等の検討が必要になる。libp2pはこのためのAutoNAT、Circuit Relay、DCUtR等を提供している。[4] 次段階の候補とし、今回実装済みとは扱わない。

署名は悪意ある情報源の虚偽、検閲、流動性の隠蔽を防がない。複数の鍵があっても運営者が独立とは限らない。ローカル設定・OS・ファイルを攻撃者が書き換えられる場合は、本実装の保護範囲外である。ノード鍵の漏洩、初回鍵交換、失効、時計の誤り、再起動をまたぐ時計巻き戻し、Sybil、DDoS、公開鍵固定の長期運用は残る課題である。

単純な全体レート制限と上限は設けたが、敵対的公開ネットワークへの耐性を実証したわけではない。ノードHTTPは情報を公開する設計であり、接続者に取引権限は与えないが、候補一覧の秘匿性は提供しない。

さらに、PCノードの分散化だけで、RPCサービス、Web配布元、各チェーンのコンセンサス、外部ブリッジの信頼条件まで分散化されたことにはならない。これらは別々に評価する。

## 次の開発順序と合格条件

| 順序 | 作業 | 完了の判定 |
|---|---|---|
| 1 | ノード候補→既存EVM検証器→見積り画面の読み取り専用接続 | 偽Factory、別チェーン、コード不一致、再編、古い準備高を除外。候補の情報源が送金権限にならない |
| 2 | 実ガス・承認費用・換算価格を用いた比較とUI統合 | 費用未計算と価格期限切れを明示。元の口座・受取人・セッション束縛を全て維持 |
| 3 | 同一チェーンの原子的な分割Router | 全入力と承認量を拘束し、部分成功・余剰資金・コールバック・税付き転送を検査。総最小受取額を実行時に保証する条件を定義 |
| 4 | ブリッジ途中状態・受取側再見積り・明示復旧 | 元チェーン確定、受取資産到着、受取側交換を別記録。失敗時に現在の資産所在を再検証できる |
| 5 | アダプター拡張と既存DEX流動性の取り込み | チェーンごとに実装・シミュレーション・独立レビュー・明示承認の試験を通す |
| 6 | 家庭用PCの接続自動化 | 複数実機、NAT、リレー停止、相手変更、スパムで試験。単一bootstrapへの必須依存を避ける |

全チェーン共通で、受入条件に満たないものは「認識できる」「候補を発見できる」「見積れる」「検証できる」「送信できる」「受取まで確認済み」を分ける。「アダプター名がある」だけで対応済みと表示しない。

最終目標は、**誰でもプールを作れ、誰でもノードを立てられ、利用者が検証された実行可能経路の中から条件に合う交換を選べる非カストディアルなネットワーク**である。単一の巨大ブリッジや中央運営の残高管理へ集約しない。
