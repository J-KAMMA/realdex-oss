# v0.23 安全性の境界

未監査・ローカル開発専用。新しい処理はチェーンへ書き込まない読み取り追跡であり、常駐relayerではない。ウォレットの保管庫へ観測を保存する処理はある。

## 保護するもの

- 検索結果を取引成功と同一視しない。既存のpacket/署名済み元取引/包含/ACK/残高差分の検査を維持する。
- ユーザーやpeerから任意の検索文字列・RPC URLを受け取らない。既存のlocal-only経路から問い合わせ先を決定する。
- ページ、結果件数、同時読取り、追跡対象数、読取り間隔に上限を置く。不完全な検索や矛盾する候補は選択しない。
- 検証に失敗した新しい候補ハッシュを保存済み参照へ昇格させない。既存の参照と異なる候補を自動で上書きしない。
- 停止操作はUIのbusyフラグや通常APIのレート制限で待たされない。ただし認証、origin、loopback、本文形式の検査は維持する。
- 停止・ロック後は古い結果を保存しない。保存キュー内でも最後に取消しを再検査する。保存失敗はロックへつながる既存処理を使う。
- 自動ロックを延長しない。再起動・再解除・復元で追跡許可を自動復元しない。所有者の操作を優先し、追跡は一件ずつ。

## 保護しないもの・未達

一致するRPC応答は独立した確定証明ではない。イベント索引が不完全・停止中なら自動検出できないことがある。既知の参照ハッシュは再照合を続けるが、検索に出ない未知の中継を発見できると保証しない。悪い候補や矛盾により停止する場合、所有者が手動の参照を確認する必要がある。

同じ1ノードへ向けた二つのURLは独立した検証主体ではない。`finalityProven:false`と`stateProofVerified:false`を維持する。観測結果を他の橋の資金解放へ使わない。

デスクトップがロックされると追跡も停止する。read-onlyの別プロセス常駐watcher、公開ネットワーク、常駐中継、client更新鍵の費用制限、OS隔離は未実装。以前の署名や中継は停止ボタンで取り消せない。

同じPC全体を侵害するマルウェア、所有者URLの漏えい、鍵漏えい、古いバックアップや並行端末の二重署名は、この追跡処理では解決しない。

## 試験の区別

新規追跡は二つの本物のローカルIBCチェーンで試験するが、各チェーンは単一validator。中継はテスト用の別主体が実行し、追跡器は送信・シミュレーション・署名を行わないことも確認する。

ブラウザHTTP/CSP試験は管理ポリシーでblocked。合成APIによる画面操作試験は別枠。既存の他VM試験や過去版の件数を、今回実行した試験数へ足し直さない。
