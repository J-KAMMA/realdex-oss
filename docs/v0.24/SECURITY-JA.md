# RealDEX v0.24 中継の信頼境界

## 所有者の資産鍵と、中継費用鍵の分離
中継は独立のCLIプロセス・ディレクトリ・暗号化ファイルです。初期化時に各ネットワークの専用secp256k1鍵を生成します。鍵の取込機能はありません。ウォレットの所有者URL、ウォレットAPI、AI MCPを呼びません。接続アダプターへ渡すデータから秘密鍵フィールドも取り除きます。

専用鍵は中継中にメモリ上へ復号されます。通常ウォレットの5分ロックとは別です。Node/JavaScriptで、文字列や複製を含む完全なメモリ消去を保証していません。同じOS利用者が任意コード実行・ファイル・メモリ・画面にアクセスできる場合の強い隔離ではありません。暗号化はscrypt＋AES-256-GCMで、OS安全領域・ハードウェア鍵・外部監査は未接続です。

## 中継者ができる操作
任意のbank送金、authz、任意callを作成しません。許可経路の元取引とパケットを検査し、必要なMsgUpdateClient（Tendermint Header）と、受取/ACK/タイムアウトのいずれか一つだけを署名します。パケットの資産・数量上限・経路・番号・宛先・送信者・期限を結び付けます。宛先は元取引から引き継ぎ、中継者が変更できるものではありません。receipt・ack・commitmentの証明はチェーンのIBCが検証します。

ただし、費用枠はサービス内の制限です。専用秘密鍵自体が漏れた場合、攻撃者は別のクライアントから費用口座を操作できます。少額の無価値試験費用だけを入れ、所有者資産や権限を付けないでください。公開利用の安全性を保証していません。

## 永続化・二重送信
署名済み取引、sequence予約、累計費用消費は同じ認証付き暗号文に含めて保存します。ネットワーク送信の前にbroadcast-unknownを別保存し、保存障害はロックして停止します。置換後のディスク同期失敗など、結果不確定な場合に旧状態を保証するわけではありません。

結果不明・受付済みは同じ取引の照合だけです。自動再送・別sequenceへの差替え・失敗した署名の予算返却はありません。未送信と記録された署名に限り、所有者が明示的に再起動し、再検査が通った後に同じバイト列で初回送信します。

強制終了後の手動ロック復旧はLinux上の死亡PIDとファイル同一性を検査します。PID再利用の場合は拒否します。悪意ある同一OS利用者や異常ファイルシステム、実電源断を包括的に検証したものではありません。ポリシーや古い保管庫コピーの巻戻し、複数端末を横断する単調カウンターは未実装です。

## 最終確定と中継完了
専用中継キューのsettled-observedはRPCから観測した処理状態です。デスクトップが独立してPoS合意・validator集合・状態証明を全検証する意味ではありません。既存の所有者用IBC追跡は別に受取・ACK・返金を照合し、finalityProven=falseを維持します。RPCが嘘をつけば可用性や費用に影響し得ますが、受取数量や資金解放はチェーン上のIBCルールに従います。

キューが完了になった後の継続的な再編監視は中継ワーカーにはありません。所有者側の読み取り追跡とは機能を分けています。新たなジョブを自動検索・登録する機能もありません。

## 未達
長時間の公開運用、複数validator、独立RPC間での一致、RPC索引遅延と運用停止からの完全自動回復、費用自動算出、ガス上限の自動変更、期限/予算更新、未解決予約の解除、キュー追加API、OSサービス登録、監査を完了していません。対応する証明/ヘッダーが大き過ぎる場合は停止します。厳密な一致検査による一時的な拒否は、黙って成功へ置き換えません。
