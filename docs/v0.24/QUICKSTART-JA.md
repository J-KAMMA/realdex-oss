2026-09-06。自設ローカル開発用、未監査、実資産禁止。本番用中継サービスではありません。

## 更新
旧ウォレット・共有ノード・試験ノードを正常終了し、暗号化バックアップと設定を保全してください。新ZIPは別フォルダーへ展開します。ウォレットの保存形式を今回変更していません。既存の秘密鍵やウォレット保管先を、新しい中継サービスへ取り込まないでください。

```sh
node app/cli.mjs start
```

従来の所有者ウォレットと読み取りノードの起動です。これだけで中継サービスは起動しません。所有者専用URLをAI・他人・中継者へ渡さないでください。追加中継はCLIで操作し、新しいグラフィカル画面やMCP権限は追加していません。

## 今回の中継機能
`relay/`が、独立した費用用鍵・暗号化保管庫・永続キューを持ちます。登録済み経路と明示した送信取引ハッシュについて、受取・ACK・タイムアウトを処理します。必要なTendermintクライアント更新も同じ中継取引に含めます。各チェーンのIBC実装がヘッダーと証明を検査します。

対象はIBC Classic、unorderedのtransfer/ics20-1、Tendermint、対応するIAVL証明形式、1ホップです。パケット転送memo、fee middleware、接続・チャネルの自動作成、任意メッセージは対象外です。専用口座には無価値の手数料資産だけを入れ、所有者の資産やauthz権限を与えないでください。

## 手順の全文
[独立中継の設定・秘密入力・起動・停止・復旧](../../relay/README.md)に、動くCLI例を記載しています。

1. 自分で確認済みのウォレット設定から、許可する経路と費用枠を指定してポリシー草案を生成します。
2. 内容を確認し、別の保管先を初期化します。ネットワークごとの新しい専用鍵が生成されます。
3. 表示された専用口座に試験用の手数料資産を入れます。ウォレット資産を自動移動する処理はありません。
4. 停止中のキューへ、元チェーンのIBC送信取引ハッシュを明示登録します。
5. ポリシーハッシュと非表示入力したパスワードで開始します。Ctrl+Cで停止します。

パスワードを引数や環境変数へ設定しません。CLIはパイプまたは専用FDで受け取ります。Bashの例はREADMEを参照してください。シェルトレースや端末共有を有効にしないでください。Windowsでの操作・復旧は未検証です。

## 上限
経路最大4、ネットワーク最大4、キュー最大32、保存した署名最大256、暗号化前450,000バイト、許可期間最大7日。費用と最大署名回数はネットワーク別の累計枠です。署名時に枠を消費し、失敗・結果不明でも戻しません。予算は署名サービス内の制御であり、鍵が漏れた場合のオンチェーン制限ではありません。

## 停止と再起動
所有者ウォレットをロックしても、中継は別プロセスで動きます。止めるには中継のCtrl+C/SIGTERMを使います。停止後の署名・送信を拒否しますが、既にネットワークへ送った取引を取り消すことはできません。

署名だけ保存し未送信の場合は、明示的な再起動後に再検査し、同じバイト列で初回送信します。`broadcast-unknown`や`broadcast`は読み取り照合だけを行い、自動再送・再署名しません。未知の取引があるネットワークでは新規署名を保留します。未解決予約の解除、期限更新、費用増額、キューの動作中追加は未実装です。

強制終了で残ったロックは、プロセスの終了を確認してから`relay/recover-lock.mjs`で手動解除します。生存中・PID再利用・所有者不一致・ファイル差替えを検出したら拒否します。ジャーナルや予算は書き換えません。古いバックアップや別端末へのコピーで予算を巻き戻す問題は解決していません。

## 実行試験
診断ツールはZIPとは別配布です。ハッシュ検査してから実行します。

```sh
python3 integration/ibc/provision.py --archive /path/to/RealDEX-IBC-Diagnostic-Toolchain-2026-09-06.zip --output /path/to/new-ibc-tools
export REALDEX_IBC_SIMD_BINARY=/path/to/new-ibc-tools/simd
export REALDEX_IBC_MUSL_LOADER=/path/to/new-ibc-tools/lib/ld-musl-x86_64.so.1
node integration/ibc/relay-demo.mjs
node app/verify.mjs --ibc --output /path/to/new-acceptance
```

デモは使い捨ての2チェーン、財布、独立した中継用鍵を作り、終了時に削除します。二つのチェーンは別の状態・genesisですが、各々は単一validatorです。二つの観測URLは同一ノードの入口です。公開チェーンや独立したデスクトップ証明を検証するものではありません。

## 残る必須条件
固定Node/依存環境、正式Solidityコンパイラ、全体Reactビルド、実ブラウザHTTP/CSP、公開テストネット、Windows、OS鍵保護、長時間運用、独立監査が未達です。通常起動に新しいnpm依存は不要ですが、全体アプリの本番ビルド済みという意味ではありません。
