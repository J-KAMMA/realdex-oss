# RealDEX v0.19 — スマートアカウント起動・更新手順

2026-09-06 / 開発版。新規の使い捨て試験鍵だけを使用してください。実資産のある鍵・既存の本番ウォレットは使用しないでください。

## 追加内容

既存のEOAを残し、そのEOAが所有する別アドレスのコントラクト口座を追加します。CREATE2生成、ネイティブ/ERC20まとめ払い、承認→経路交換→承認取消し、ERC-1271署名検証、期限・資産・受取先・予算付き補助鍵に対応しています。

ERC-4337のEntryPoint/UserOperation/bundler、paymaster、EIP-7702、パスキー、マルチシグ、所有者交代・紛失鍵回復は未実装です。所有者は作成後に変更できません。AI MCPの権限は増やしていません。

## 通常起動

旧プロセスを正常終了し、暗号化バックアップと設定を保全します。ZIPは別ディレクトリへ展開してください。

```sh
node app/cli.mjs start
```

追加ローカルサービスはNode 22.16.0以上で起動でき、通常起動にはnpm install・Anvil・Solidityコンパイラは不要です。ルートReactアプリ全体のビルド条件は別です。

ウォレットはターミナルに表示される所有者専用URLから開きます。`#key=`を含むURLはAI・共有ノード・他人へ渡さないでください。保存先は既存の`~/.realdex-app/`、ウォレット単独起動では`~/.realdex-wallet/`です。自動移行・本番ネットワークへの配置は行いません。

## 最初から動きを試す：使い捨てデモ

以下はLinux x86-64の試験経路です。既存の試験用Anvilと固定nightlyコンパイラを、後述のハッシュで照合して準備します。

```sh
export REALDEX_ANVIL_BINARY=/absolute/path/to/anvil
export REALDEX_EXPERIMENTAL_SOLJSON=/absolute/path/to/soljson.cjs
node integration/smart-account/demo.mjs
```

デモは新しいローカルAnvil、無価値の試験残高、一時保管庫を作り、アカウント生成・まとめ払い・補助鍵の予算検査・ERC-1271検証・全補助鍵取消しを実行して削除します。利用者の通常保管庫や公開チェーンは使用しません。

画面で操作する場合：

```sh
node integration/smart-account/devnet.mjs
```

生成したFactory・口座・試験残高がある所有者URLと、この使い捨て保管庫のパスワードをターミナルに表示します。Ctrl+Cで終了すると試験チェーンと保管庫を削除します。通常サービスとは別の一時ディレクトリ・空きポートを使用します。画面の実HTTP結合はこの環境では管理ポリシーにより未確認です。

## 自分のテスト環境で登録する

最初に、対象ネットワークへ`RealDexSmartAccountFactory`を配置する必要があります。アプリは未知のFactoryを自動で配置せず、既存の自前DEX Factoryを流用もしません。ローカルデモはこの配置を自動で済ませます。バイトコードとABIは`wallet/smart-account/build.json`にあります。

1. EVMテストネット設定（2〜4 RPC、genesis hash、費用上限など）と、所有者のローカルEVM口座を準備します。
2. 「スマートアカウント」→「Factoryから作るアカウントを登録」で所有者・ネットワーク・Factory・salt・表示名を選びます。
3. 生成先と所有者を確認し、表示された`REGISTER <生成先>`を全文入力します。この段階では送信しません。
4. 新しいバックアップを保存・再読込して検証します。登録前のバックアップ確認だけでは署名できません。
5. 「アカウントをデプロイ」を準備し、別の承認欄で全内容を確認します。送信チェックは既定OFFです。
6. ネイティブ通貨は「所有者から入金」で追加できます。ERC20は既存の通常送金機能等から、生成・コード照合済みのスマートアカウントへ送ります。

Factoryとアカウントは同梱バイトコード全体、所有者・生成元のimmutable値、生成先計算を照合します。未知のコードハッシュを入力するだけで許可される仕組みではありません。この一致は監査完了の意味ではありません。

## ガス代と資産の区別

通常操作のガス代は所有者EOA、補助鍵送金のガス代は補助鍵EOAが支払います。送る資産はスマートアカウントの残高から出ます。アカウントに十分な資産があっても、実行する鍵にガス代がなければ送れません。ガス代肩代わりやトークン建てガス支払いはありません。

まとめ払いは最大8件です。交換は登録済みの1〜4プールに限定し、有限額承認・Router交換・承認ゼロ化を一つの取引へまとめます。途中で失敗すれば全呼び出しがrevertしますが、失敗した取引のガス代は発生し得ます。ネットワーク費用込みの最適経路自動探索は追加していません。

## 補助鍵

所有者と別のローカルEVM口座を作り、バックアップしてから許可します。資産1つ、受取先1つ、1回上限、UTC暦日上限、許可の累計上限、最大7日の期限を指定します。日次は直近24時間ではありません。限度は金額換算ではなく資産数量です。複数の補助鍵の予算はそれぞれ独立で、所有者本人の全権限を制限するものではありません。

**PCのロック・AI停止・アプリ終了・接続トークン取消しだけでは、既にチェーンへ付与した補助鍵の権限は失効しません。** 個別取消し・全補助鍵取消しの取引を送って収録を確認するか、有効期限を待ちます。既に実行された送金は取消できません。再付与は新しいgenerationと予算を設定する所有者操作です。

本版の補助鍵操作は所有者用画面/APIだけです。既存AI MCPへの自動送金接続や秘密鍵出力は追加していません。

## ERC-1271

文字列署名はアカウント・chain ID・期限・署名世代に結び付けます。改行を含むUTF-8文字列を扱い、隠れた方向制御文字等は拒否します。「過去のERC-1271署名を失効」は署名世代を進めます。

署名ファイルは認証能力を持つため、通常のログとして配信しないでください。任意dappのpersonal_signへは自動接続しません。同じアカウントでの再利用防止には、相手アプリ側のchallenge/nonceが必要です。

## 試験用ツールの固定値

- Anvil本体: 50,363,200 bytes / SHA-256 `2c403563da1605bfda3e6892895209269f6959033af818b54ccd2f15b92df858`
- 固定nightly soljson: 9,222,236 bytes / SHA-256 `598ddf764460231e865d096010be277649d979c6d9c4d51a7a4b4036420845df`
- Compiler: `0.8.37-nightly.2026.9.3+commit.f67cf4f2.Emscripten.clang`

検証スクリプトはファイル種別・サイズ・ハッシュを再確認します。Anvilは実行権を付け、soljsonは`.cjs`として読めるファイルにします。どちらも他ユーザー書込み可にせず、シンボリックリンクを指定しないでください。固定nightlyは正式Solidity 0.8.24の検証に代用されません。

```sh
node integration/smart-account/run.mjs --output smart-acceptance-new
node wallet/test/run.mjs
node app/verify.mjs --full --output full-acceptance-new
```

出力先は未作成のディレクトリを指定します。必要ツールがなければ合格ではなくblockedになります。全体検証と独立監査は未達です。

## 更新・復元

新しいスマート口座・署名を保存した保管庫を旧版で上書きしないでください。最新バックアップで生成先・所有者・署名履歴を保持しますが、古いバックアップや別端末で署名履歴が巻き戻る問題を完全に解決するものではありません。オンチェーンのexecutionNonce/sessionNonceと、所有者EOAのnonceを別々に検査します。
