# RealDEX v0.19 — スマートアカウントの権限境界

## 何を信頼するか

所有者のEOAは全資産を操作できます。秘密鍵は既存のローカル暗号化保管庫へ置き、共有ノード・AI用MCP・接続dappに新しい署名権限を渡していません。署名サービス自体・OS利用者が侵害された場合まで保護するものではありません。ハードウェア鍵保管や独立監査は未完了です。

Factoryと口座は非upgradeable、所有者と生成元はimmutableです。owner交代・紛失回復・guardian・multisigはありません。元のEOAへ委任コードを設定せず、別アドレスへコントラクト口座を作ります。本版はERC-4337のアカウント抽象化システムではありません。

所有者はコントラクト上ではexecuteBatchを通じて幅広い外部callを実行できます。一方、RealDEXのUI/署名サービスは送金と登録済みRouterへの限定操作だけを受け付けます。これは「owner自身にも予算上限がある」という設計ではありません。

## 新規の保護

- CREATE2に所有者とsaltを束縛し、別人が先に生成してもownerを取得できない初期化。Factory全runtime、口座全runtime、immutable値とgetterを照合します。
- 一括実行の失敗、偽のERC20成功値、期限切れ、executionNonce再使用はrevertします。再入可能な状態更新を共有guardで保護しています。
- 補助鍵は一資産・一受取先・per-call/UTC日次/lifetime/期限に束縛します。generationで古い許可の再利用を防ぎ、個別取消し・全体epoch・補助鍵nonceを別々に保持します。
- 補助鍵のトークン移転では戻り値と前後残高を検査し、失敗時には予算とnonceも戻ります。トークンcodehashも固定します。ただしプロキシの背後や虚偽のbalanceOfなど、任意トークンの意味まではcodehashだけで証明できません。普通の所有者ERC20まとめ払いは戻り値を検査しますが、受取側残高差分を契約内で厳密保証する一般的仕組みではありません。
- ERC-1271はraw owner署名を使わず、アカウント・chain ID・期限・署名epochを含むEIP-712 digestを検証します。high-S、長さ、v、期限、世代を検査します。同じアカウント内のアプリケーション再利用防止はアプリ側の仕事です。
- 署名・nonce予約を暗号化保存後に初回送信し、送信前再検査、ロック世代の照合、保存障害時停止を行います。結果不明で別の支払いを作りません。

## 特に重要な制限

**ローカルのロックやAI停止と、オンチェーンの権限取消しは別です。** 補助鍵が他の場所へコピーされていれば、ローカルサービスを止めても、許可範囲内で直接送金できます。取消取引が反映される前の取引は成立し得ます。取消しは過去の送金を元へ戻しません。

予算は補助鍵ごと、UTC暦日ごとです。UTC日付をまたぐと短時間に二日分を使えることがあります。rolling24hではありません。再付与は意図的に累計予算を新しくするowner操作です。ガスは補助鍵自身が払い、オンチェーン予算に含めません。

メインネット識別子は既存のローカル署名制限で拒否します。ただし「localhost」「テストチェーンID」という申告だけで公開資産を絶対に扱わない証明にはなりません。実資産のない試験鍵のみを使ってください。

## 実行結果の検査

バッチのreceiptは実行nonceとcallsHash、生成はowner/Factory/salt、補助鍵支払いはgeneration/nonce/amountをイベントと照合します。イベント一致は独立した残高・finality証明ではありません。`smartAssetBalanceChangeVerified:false`と`smartFinalityProven:false`を返します。偽造・欠落・重複イベントは成功に昇格させません。

試験は一つのAnvilに二つのHTTP転送口を付けた環境です。合意・MEV・公開mempool・外部RPCの独立性・実再編・監査を検証したものではありません。公開テストネットとWindowsも未確認です。

## 保存と後方互換性

口座記述・メッセージ・署名済み取引を読み戻す際、owner、生成先、chain、署名digest、実際のsigned calldata/valueを照合します。スマートアカウント登録をバックアップ対象に加え、新しいバックアップ検証を要求します。既存保管庫の生成鍵は変更しません。古いバックアップ・別端末でのロールバック安全性を全面保証しません。
