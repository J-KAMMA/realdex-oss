# v0.20 安全性と制限

## 権限の境界
新規の署名は所有者専用UI/APIのみです。既存AI MCP・外部アプリ接続・共有ノードの権限は増やしません。グラントを外部AIのアドレスへ付与すること自体はできますが、本版にAI用authzクライアントを自動設定する処理はありません。

Cosmos authzはネイティブの代理実行です。新しい契約口座、Factory、所有者回復機構をデプロイするものではありません。資産はgranterに残り、MsgExecの署名者granteeが手数料を払います。Feegrantは使いません。

チェーン側で強制するのは、SendAuthorizationに含まれるdenom・累計の残り支出枠・許可受取先・有効期限です。日次リセット・1回上限・最大回数・PCロック・所有者鍵の回復は、このネイティブ許可にはありません。所有者は通常送金を自由に行えます。複数granteeの許可は別予算です。

RealDEXの新規作成は資産1種類、受取先1口座、最大7日の期限に限定します。空allow_listやGenericAuthorization、Feegrant、staking、IBC、任意のAny、複数/入れ子MsgExecを生成するAPIはありません。外部の広い許可は実行せず、取消しのための未対応状態として表示します。複数種類の許可を持つ組については全件処理せず、明示的に未対応として停止します。

## 保存・取消し
署名と通常Cosmos送金と共通のsequence予約を一つの暗号化保存へまとめます。送信開始も先に保存し、保存障害はロック・送信停止です。ロック世代・所有者確認・バックアップ確認・未解決取引保留を既存経路と共有します。

PCのロックではオンチェーン許可は消えません。取消しが収録される前に、許可内の送信が先に実行される可能性があります。既に実行した送金は取消せません。同じgranter/grantee/MsgSendへの再付与は新しい予算で、標準authzにEVM版の独自epochはありません。古い未収録の署名が、同じsequence・期限と再付与された権限を満たす場合まで永久に無効になるわけではありません。

APIは既存許可を上書きしません。ただし、標準MsgGrant自体にcompare-and-swapはなく、別の所有者クライアントと競合した場合のネイティブな原子比較はありません。署名直前/初回送信直前のRPC再検査で防げる範囲と区別してください。

送信結果不明、署名だけ保存、未対応の結果ではsequence予約を自動解除しません。別の依頼キーは別の要求です。過去のバックアップ・複数端末のローカル履歴を同期する仕組みではありません。ただしnative allowanceはチェーン状態のため、過去のバックアップへの復元で消費分が補充されることはありません（実ノードで確認）。

## RPCと決済
RPCは設定されたローカル接続先のみで、公開RPCへfallbackしません。ブロック高・checkpoint・アカウント・grantの照合を行います。Cosmos SDKで未存在grantをmsg_type_url付きで検索するとエラーになるケースを実ノードで確認したため、granter/granteeペアを検索し、成功応答の空配列だけを未存在と扱います。HTTPエラーを未存在へ変換しません。

Merkle包含先のrootやblock、grant状態、実行結果はRPC由来です。独立したvalidator署名・light client・アプリ状態証明ではなくfinalityProven/stateProofVerifiedはfalseです。複数URLも独立した合意の証明ではありません。ブリッジ資産の解放には使いません。

同じ収録ブロック内に別のgrant更新・代理送金があり、期待した残り枠と終端状態が一致しない場合は完了と断定せず保留します。許可操作のcompletedと、資産移動のreceivedは分離します。

## 本番未達
対象は自設realdex-local-*チェーンの通常BaseAccountだけです。chain IDだけでは同名の別チェーン間の再利用を暗号的に防げず、checkpointは標準署名の一部ではありません。実資産キーは使用しないでください。

Cosmos SDK試験は固定した開発simdの単一validator。公開チェーン、異なるSDK配備、Windows・OS鍵保護、第三者監査、依存を揃えたReact全体ビルド、実ブラウザHTTP/CSP、正式Solidity0.8.24は未達です。他の非EVMでのスマートアカウント、ERC-4337/bundler/paymaster、パスキー、回復、実ブリッジも完成していません。
