# RealDEX v0.18 — 信頼境界

## 今回変更したこと

Aptosの実ノードが返すシミュレーション形式に合わせ、シミュレーションに限りtype省略を受け入れます。確定取引のtype・送受先・署名・関数・引数・sequence・ガス・期限の検査は維持します。RPCの短縮アドレスをバイト同一性で比較しますが、所有者入力を短縮形へ緩和しません。

Stellar/Aptosの共通REST入力で、UTF-8不正、重複JSONメンバー、危険なオブジェクト名、孤立サロゲート、過大な深さやノード数、精度を失う裸の数値を拒否します。大きな整数はプロトコル通りの10進文字列として処理します。パスとqueryを用途ごとに限定し、任意のqueryをそのまま外部へ転送しません。

Aptosの成功応答ではチェーンID・台帳versionのヘッダーを検査します。履歴読み取りでは要求versionがサーバーの報告する範囲内かを確認します。ただし、ヘッダーそのものは信頼の証明ではありません。要求された履歴状態であることを暗号学的に証明するものではありません。

Stellarは一つの通常Paymentに限定したTransactionResult XDRを全バイト読み、手数料、取引結果、操作数・種類・結果、拡張終端、HTTP応答の成功フラグの整合を検査します。未知のコードや切れた失敗データは決済済み失敗へ昇格させず、未解決のまま残します。送信元sequenceが取引sequenceに達していることも必要です。受付段階の拒否を操作実行済みと同一視しません。

## 変更していない境界

共有ノード、AI、MCP、接続アプリへ非EVMの署名権限は追加していません。鍵、パスワード、秘密閲覧鍵を外部サービスへ渡しません。Aptosのシミュレーションに実署名は使いません。送信は所有者の明示承認と永続保存の後です。

メインネット制限、登録した接続先・checkpoint・費用・数量制限、同じ依頼の重複防止、未解決取引による保留、署名・sequence予約の保存、ロック後の旧要求失効を維持します。再送、置換、保留の強制解除、バックアップ形式の自動移行は追加しません。

## 依然として証明していないこと

Aptosは一つのローカルvalidatorでMoveを実行した試験です。二つのURLは同じノードへの中継であり、独立した合意ではありません。LedgerInfo署名・検証者集合・台帳や状態の証明を独立検証していません。

Stellarは形式・署名・合成HTTP試験までです。実Stellar CoreやSCPの検証、独立した前後残高証明はありません。結果の型検査を強めても、二つの接続先が共に虚偽を返す問題は解消しません。

`finalityProven` はfalseのままです。今回の観測結果をブリッジの資金解放に使いません。秘密資産送金、非EVMのDEX、ブリッジ、上位100位の全機能完成は未達です。

同じPCの管理者・マルウェア・任意シェル権限を持つAIから、鍵を完全に隔離するものではありません。OSの鍵保護・ハードウェア保護・署名付き更新・独立監査は別の課題です。固定ツールハッシュも独立監査の代わりにはなりません。

## 互換性と可用性

不正または未対応の応答は、取引未解決として保留する方向です。以前受け入れていた不完全な模擬RPCや、中継でAptosヘッダーを落とす構成は動かなくなる場合があります。検査を無効化せず、仕様に沿うローカル接続先を修正してください。

古いバックアップや別端末での二重署名は、現在の保管庫内のsequence予約だけでは強制できません。履歴を失った復元を送金の取消しとして扱わず、実資産で使わないでください。

## 数値変換前の検査

数値変換後に安全な整数かを調べるだけでは、端数の丸め・underflowを見逃します。元の字句と変換値を照合し、共通RESTの非引用数値は整数表記に限定します。これにより対応外のRPCが指数表記や小数表記を返した場合も停止します。互換性より曖昧な解釈の拒否を優先した限定仕様です。暗号学的な台帳証明や、偽の整数値の検出とは別です。
