# v0.15 セキュリティ境界・残る制限

## 今回の権限

追加APIは所有者専用です。既存のローカルHost・Origin・所有者capability検査を維持しています。共有ノードとAIには新しいBitcoin署名権限を付けません。認証パスワード・秘密鍵・署名済み生データをCoreの署名RPCへ渡しません。Coreの署名・財布管理メソッドはtransportのallowlistにありません。

RPCは127.0.0.1のHTTPルートURLだけで、リダイレクトを拒否します。Cookieは所有者が指定した絶対パスの通常ファイルから都度読みます。POSIX所有者・mode、symlink・hardlink・inode変化、サイズを検査します。Cookieの内容とサーバーが返した任意のエラー本文をAPI・ログへ返しません。JavaScript文字列の完全なメモリ消去を保証するものではありません。

CookieはCoreへの権限を持ちます。ループバックの中継先が悪意を持つ場合、渡したCookieを悪用できます。接続先とOSを信頼する境界は残っています。同一PC全体の侵害、OSサンドボックス、ハードウェア保護は未解決です。

## 状態・署名・送信

genesisだけでなく、利用者のcheckpointを固定します。RPC全体のtip、同期、txindex、入力状態が一致しなければ停止します。署名内容はP2WPKHの自分の入力、受取出力、自分へのお釣り、固定総手数料、SIGHASH_ALLに限定します。金額はJSONの数値を文字列化して読み取り、BigIntでsatoshiへ変換します。

署名前と初回送信前にUTXOの未使用状態・資金元raw transaction・成熟等を再検査します。署名後はtestmempoolacceptでtxid、wtxid、仮想サイズ、総手数料を比較します。実際の受付はこの後なので、検査成功が将来の採掘を保証するわけではありません。

署名と入力予約を保存し、ネットワーク送信前にbroadcast-unknownを永続化します。保存失敗は送信せずロックします。ファイル置換後の同期失敗は保存結果不確定であり、必ず旧状態へ戻ると保証しません。ネットワークの受付後にロックしても既に出た署名を無効化できませんが、古い応答が新セッションの状態を書き換えないようにします。

初回送信のあとに再送・RBF・新署名を自動発行しません。署名済みの入力予約は、観測欠落やreorgだけで解除しません。異なる依頼キーは別の支払いとして扱うため、同じ請求の意味的重複を完全には検出しません。

## 収録証拠

取引本体・txid/wtxidと、保存した署名済みバイト列を比較します。ヘッダーhashとMerkle rootをローカルで再計算し、署名したtxidがブロックへ含まれることを結び付けます。しかし、PoW・難易度・ヘッダーチェーン・ネットワークの合意は独立検証しません。active chainと高さはCore RPCの観測です。`finalityProven` はfalseです。

確認済みだった取引も再照合できます。証拠が消えた・不一致なら現在の受取観測を撤回します。履歴の観測値は保存時点のもので、自動的な最新監視・ブリッジ解放証拠にはなりません。

## 復元・容量

同じ保管庫の正しい最新バックアップなら予約が残ります。古いバックアップ、別端末、別ソフトからの署名をローカル履歴だけで禁止できません。プロトコルによる競合検出と、このアプリの予約は別です。署名済みファイルや別端末の操作を取り消せません。

既存の非EVM履歴128件等の保存上限を維持します。安全な履歴アーカイブ・移行、HD鍵とお釣りアドレスのローテーション、PSBT、ハードウェア財布、RBF、mempool再配信は未実装です。お釣りは同一口座に戻す限定実装で、プライバシー最適化ではありません。

## 試験の範囲

Bitcoin Core CI開発ビルドをハッシュ固定して実行し、ローカルregtestの実署名検証、mempool、採掘、UTXO変化、ブロックinvalidate/reconsiderを検査します。二つのHTTP入口は同じ一つのCoreへ転送します。独立ノード、P2P再編、公開チェーン、電源断、Windows/OS保護、外部監査の試験ではありません。

ブラウザHTTPがポリシーで遮断されたため、UIは合成APIを使うオフラインDOM試験です。署名サービス→実CoreのHTTP検証と、ブラウザ→署名サービスの完全なHTTP/CSP検証を混同しません。
