# RealDEX v0.11 — 実EVM検証・保管庫の保存障害対策

## 基準と訂正
基準は `RealDEX-Production-Hardening-Preview-2026-09-05.zip`（v0.10）。SHA-256は `2f40d6c071695c93d6e0d9a136708354dcb0ab6660019140f98782c674980102`。923 ZIPエントリー、FILES.sha256対象922ファイルを今回の環境で照合しました。ZIP自身の整合性検査にも合格しています。

直前の応答にあった「v0.9しか案内できない」「v0.10の配布物を確認できない」という説明は、保存済みZIPの存在と一致しませんでした。作業ディレクトリは消えていても、v0.10 ZIPは残っていました。未保存の作業を推測で復元せず、この確認できたv0.10を基準にしています。v0.10添付記録の選択試験数は1,458件であり、別の応答にある1,437件を今回の基準にはしていません。

## 修正1：パスワード変更失敗後の解除状態
`Vault.changePassword` の保存失敗経路は、通常の `save` と異なり、エラーが発生しても旧鍵とセッションをメモリ上に残していました。保存前エラーだけでなく、rename完了後のディレクトリfsyncエラーでも解除状態が残ることを再現しました。後者では、ディスクに新パスワードの暗号文、メモリに旧パスワードの鍵が同時に存在し得ました。

修正後は保存を試みて失敗した時点で即時ロックし、鍵Bufferをゼロ化、口座の秘密値参照を切り、epochを更新します。待機していた古い操作も実行されません。再試行や新旧ファイルの自動上書きはしません。4件の回帰試験は修正前に4件失敗、修正後に4件成功しました。JavaScript全メモリの完全消去やOS侵害への耐性を主張するものではありません。

## 修正2：試験ログの不完全な合否判定
従来のTAP集計は、存在しないカウンターを0と見なし、同じ項目が複数あると最初の値だけ使っていました。欠落、連結、桁あふれした集計を成功として扱うケースを再現しました。

修正後は tests/pass/fail/cancelled/skipped/todo をそれぞれ一つずつ要求し、安全な整数か検査します。省略をゼロと見なしません。15ケース中、旧版では12ケース失敗、新版は15ケース成功。正常なCRLF形式も受理します。これは信頼できるテストプロセスの出力整合性検査であり、悪意あるソース自体から独立した証明ではありません。

## 追加：依存なしの実EVM送金試験
以前取得されていたFoundryのアーカイブを、保存されたGitHub Actions digestと照合しました。Anvil本体は `2c403563da1605bfda3e6892895209269f6959033af818b54ccd2f15b92df858`。バージョン1.8.1-nightly、commit `239283e6e86545c1517cac411730d316352160a6`。これは固定した試験用ツールであり、本番ウォレットの依存ではありません。

15シナリオで、実Anvilプロセスにトランザクションを送り、EVMが返した状態を検査しました。EIP-1559/legacy署名、残高と手数料、nonce、AI同一要求の重複防止、応答喪失、採掘待ち、予算の同時要求、確認数、ロック、コード変更、genesis束縛、バックアップ後のnonce予約が対象です。

ブロックの巻き戻しはAnvilのsnapshot/revertを使った実状態変更です。模擬JSONの書換えではありませんが、分散ネットワークの合意・再編・ライトクライアント証明を試験したわけではありません。二つのHTTP口は一つのEVMへの透過転送です。応答喪失試験だけはEVMからの応答を意図的に破棄しています。

最初の応答喪失試験では、受付直後に採掘済みだと仮定して残高差を検査し、0と観測しました。試験を採掘待ちの有限ポーリングへ訂正しました。ウォレットの成功判定や確認数を緩めたものではありません。

`integration/anvil/run.mjs` は独立した結果とソース整合性を保存します。`app/verify.mjs --full` へ `native-real-evm` ゲートを追加し、ツール欠落時はblockedにします。root契約試験・コンパイル・ブラウザのゲートは置換も削除もしていません。CIへ固定Anvilの取得・照合ステップも追加しましたが、GitHub上でのCI成功は今回確認していません。

## 検証の区分
最終の件数、ログハッシュ、配布物の照合は同梱 `wallet/evidence/v011/` のJSONを正本とします。追加選択試験は保管庫4件、TAP15件、Anvil入口5件。実EVM試験15件は、模擬RPCの試験とは別枠で記録します。Python/cryptography/OpenSSL等による96ケースはこれらに足し直しません。

実行環境はLinux x86-64、Node22.16.0。全Reactの固定Nodeは24.14.0で、同一ではありません。`npm run build` はReact/ethers/Vitest等の依存不足で失敗しました。npm取得はDNSエラー。固定Solidity0.8.24取得も失敗し、AMMコンパイル・Hardhat統合試験は未実行です。ブラウザのループバックHTTPは管理ポリシーで遮断され、実ブラウザ統合はblockedです。今回の実EVM試験ではSolidity契約をコンパイル・配備していません。

## 維持した境界
既存contracts/、src/、package.json、pnpm-lock.yamlは変更していません。メインネット、ICP/Solana送信、非公開資産の送金、AIのDEX/bridge操作、鍵のOS保護、NAT越えの未完了状態は維持します。公開配備、ユーザー資産の送金、ユーザー保管庫の読み取りは行っていません。
