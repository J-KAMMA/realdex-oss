# v0.11 安全性と本番移行の制約

## 今回確認できた保護
パスワード変更の保存失敗後に、旧メモリ鍵を残して操作を継続しないよう修正しました。AIの予算予約・nonce・履歴保存は維持し、実EVMで重複要求、応答喪失、状態巻き戻し、確認数、現在のバックアップからの復元を確認しました。

Anvil試験は、固定バイナリ、単一ノード、使い捨ての鍵、ローカルで作ったテスト残高のみです。公開RPC、フォークURL、既存ウォレットは使いません。バイナリのハッシュ照合は取得物の一致を示すもので、そのツール自体の独立監査ではありません。

## 依然として保証していないこと
- 古いバックアップへ巻き戻す／複数端末で同じ鍵を使うことでのAI予算リセット防止。今回の復元試験は取引後の現在のバックアップです。
- 同一OSユーザー、管理者、マルウェア、任意シェルを持つAIからの鍵保護。Nodeプロセス分離はOS隔離ではありません。
- 全チェーンの経済的・暗号学的確定、独立フルノード合意、トークン実装の安全性。
- AMM実コードのコンパイルと交換、全React画面、実ブラウザ統合、Windows実機。
- 公開テストネット・メインネット・クロスチェーン決済・秘密取引の実行。

## 保存エラー
ファイル置換後にディレクトリ同期が失敗すると、新旧どちらが永続化されたか確定しない場合があります。必ず旧状態へ戻るとは表示しません。即時ロックして、元ファイルを保全し、再読込みで実際の状態を確認します。保存に失敗した取引をAIが勝手に再構成・再送する権限はありません。

## 本番判定
選択テストの成功と、native-real-evmの成功は別のゲートです。どちらも、本番承認ではありません。既存root-build、root-contract-tests、real-evm-wallet-integration、local-compilation、browser-http等を残しています。さらに公開テストネット、OS鍵保護、独立監査、リリース署名・更新検証が必要です。productionReadyはfalseを維持しています。
