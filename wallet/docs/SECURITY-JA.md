# 脅威モデル・セキュリティ境界・未実装

## 実装した防御

鍵・口座・履歴はscrypt（N=131072,r=8,p=1）とAES-256-GCMで暗号化。ランダムな16バイトsalt、12バイトIV、16バイト認証tagを使い、形式・KDFパラメーターもAADへ束縛する。パラメーターを勝手に弱くするバックアップを拒否する。Unixでは専用ディレクトリ700、ファイル600、単一writer、通常ファイル/owner/link検査、fsyncを伴う書換えを行う。

署名APIは127.0.0.1にだけbindし、正確なHost・Origin、起動時のUI capabilityを要求する。共有ノードとはポート・プロセス・APIを分ける。dAppのセッションは鍵APIへ使えない。CSP、frame拒否、no-store、限定CORS、サイズ・時間・キュー制限を使う。

EVMはlow-S署名、署名済み取引の厳密再デコードと送信者復元、chain/genesis/nonce照合、明示操作別のABI検査を行う。権限取消しを署名直前と未送信の送信直前に再検査する。未知の呼出し、無制限承認、未対応取引型、未知の費用モデルを自動承認しない。

## 保護できていないこと

**これはOSのセキュアエンクレーブでもTauri/Stronghold実装でもない。** 同じOSユーザー権限のマルウェア、ブラウザ拡張、キーロガー、改ざん済み実行ファイル、管理者権限、プロセスメモリ読取りは防げない。共有ノードと別プロセスであってもOSを共有する。UIの見た目を独立した信頼済み表示装置とみなさない。

Node/JavaScriptとJIT/GCでは完全な秘密消去やconstant-timeを保証できない。バッファの消去は行うが文字列・コピーが残る可能性がある。パスワード入力長の検査は強度保証ではない。脆弱なパスワードに対するオフライン攻撃は残る。OS鍵保管、TPM、ハードウェアウォレット、秘密共有、BIP39/HD、盗難端末の遠隔失効はない。

バックアップは秘密鍵と履歴を含む。古いバックアップは当時のパスワードで有効なまま。パスワード変更は鍵変更でも過去の複製の失効でもない。耐ロールバックカウンターはない。最新履歴のない復元から再送しないこと。複数端末が同じ鍵を同時に使うnonce管理は実装していない。

## チェーン・契約の限界

RPC一致はコンセンサス証明ではなく、複数URLが同一運営者の場合もある。genesis pinは利用者が独立に確認する必要がある。RPCのreceiptに基づく状態はreported-confirmed/revertedであり、再編成監視やlight clientによるfinality検証はない。

契約のruntime hashとsimulationは、constructor/storage/upgrade権限/トークンの全挙動を証明しない。Proxy、fee-on-transfer、rebasing、悪意あるトークン、チェーンの独自手数料・改変VMの汎用対応はしない。登録したcode hashは「安全性を監査済み」の印ではない。Pool生成由来・本人性の従来課題は未解決であり、実験署名用の手動allowlistを自動昇格に使わない。

署名済み取引の送信を開始した後は、ロックや接続取消しで取り消せない。再送は同一バイト列のみ。取引置換、手数料引上げ、複雑な並列nonce、ガススポンサー、スマートアカウント署名はない。履歴は1000件/ファイル1MiB等の上限があり、サイズで先に停止する場合もある。アーカイブ未実装なので実運用の無期限運転を保証しない。

ICP/Solanaの署名コーデックはオフラインの開発API。ICP証明書・委任・台帳実装同定、ICRC送信結果回復、Solana blockhash期限・Token2022・生チェーン送信は結合していない。画面からは送信できない。privacy coinのspend/view key、秘密スキャン、匿名ブリッジも未実装。

## サプライチェーンと監査

ECDSAにはnoble-secp256k1 2.2.3の上流index.jsをバイト不変で同梱した。MIT表示とGit blob/SHA256照合は改ざん検出の材料であり、暗号監査ではない。旧バージョンの上流監査を本版の監査と称しない。最新安全性や脆弱性が将来変わり得るため、リリース前に再調査・独立レビューが必要。

この開発版自体は第三者監査未実施。実資産に使用しない。試験合格件数を「資金安全性の証明」「全チェーン動作保証」として使わない。
