# v0.9 セキュリティ境界と未解決事項

2026-09-05。監査報告ではなく、実装上の境界と試験範囲の記録です。実資産禁止。

## この版で強化した境界

成功・失敗の受取証は再照合可能になりました。署名済み取引本体との一致、ブロック内のindex、ログの帰属、ガス条件、確認数、終了時のブロック整合を確認します。古い成功観測だけを残す状態を修正しました。再照合に失敗したときは成功・受取の現在観測を取り消し、過去の観測は過去として保持します。任意RPCの一致は暗号学的コンセンサス証明ではありません。

手動再送の排他は非同期RPC処理の完了まで維持します。ロックepochを送信前後で照合し、ロック・再解除後に古い送信手順が再開しないようにします。ただし送信を開始したバイト列を後から回収できるわけではありません。

AI previewは読み取り・検査だけです。予算の予約、保管庫操作時間の延長、権限の変更、署名、再送をしません。previewから実送金までに状態は変わり得るため、署名時に再検査します。同じ論理支払いに異なるidempotencyKeyを使う事故を、この仕組みだけで完全には検出できません。

所有者DEXフォームは、既存の限定したデコーダー／署名ポリシーへ構造化した依頼を渡します。未知のcalldataやルーターを自動採用せず、主な数量を署名サービス側で整数化します。ERC20のdecimalsは直接送金だけでなく承認・DEXで使うトークンも検査します。実行コードが一致しても状態・プロキシ実装・転送挙動まで安全とは限りません。

既存ネットワーク設定の置換では新旧設定のdigest、保管庫epoch、90秒の期限と確認文を検査し、進行中の署名／送信があれば拒否します。適用前に全接続・AIを停止してロックし、古い非同期依頼を失効させます。保存失敗後に保管庫を自動で再解除しません。所有者による許可リスト更新は、契約監査ではありません。

ランチャーはノード署名鍵とウォレット鍵を別の保管先・プロセスで扱います。ただし同一OS利用者に対する強い隔離やsandboxではありません。共有ノード設定を公開送信対応へ変更しません。今回起動した子だけを終了させ、他アプリのプロセスや古いロックファイルを勝手に削除しません。

## 残る重大な制約

- ローカル署名器・暗号化保管庫・DEX契約の独立監査は未実施。OS侵害、デバッガ、画面制御、任意ファイル権限を持つAIからの保護は保証しません。
- 所有者の起動URL、パスワード、暗号化バックアップ、AIトークンを混同しないでください。公開ノードへ秘密情報を配置しません。AIに任意シェルを与えた状態を限定MCPと同等には扱いません。
- 署名済みバイト列は外部に持ち出せば再利用され得ます。ロック・取消はチェーン上の取引取消ではありません。
- AIの制限はオフチェーンのローカル規則です。古いバックアップの復元、同一鍵の別端末利用、別権限・別論理キーの利用には、オンチェーン予算上限のような全端末横断の強制力はありません。
- safe/finalizedはRPCが返す観測です。light clientや状態証明の検証、強い再編耐性、送信先の実残高変化・税引トークン・リベース・upgradeable tokenの保証ではありません。
- 手動で登録した複数RPCが同じ運営者・同じ改ざん情報源を使う可能性があります。URLの個数を独立した信頼源の数とみなしません。
- Pool identity生成はローカルartifact整合検査です。今回実コンパイルは未完了であり、偽造されたartifactだけを根拠に安全性を主張しません。生成履歴の証明、任意初期storageの同一性、トークン実装の同定は別問題です。
- DEX比較は登録済み直接Poolの追加費用前出力です。ネットワーク全流動性、分割実行、ブリッジ、フロントラン・MEV耐性を含む最適性はありません。残る有限承認の取消は別操作です。
- 全体React build/test、実Solidityコンパイル、実EVM用シナリオ、ブラウザHTTP/CSP/CORS統合、公開チェーン送信、Windows/OS鍵保護は今回未検証。
- ICP/非EVM送信・復旧、privacy wallet、クロスチェーン実行、Tauriインストーラー、自動NAT越えは未完成です。候補チェーン164件という旧版の登録数を、本版の署名・送信対応数へ転記しません。

## 試験の読み方

合成RPCは入力検査と状態遷移を制御して試すためのサーバーです。EVMを実行せず、トークン残高を実際に変えません。オフラインDOMはUI操作試験ですが、実HTTP/CSPとネイティブ暗号処理を統合した試験ではありません。実EVM用テストファイルの存在と、そのテストに合格したことは別です。

`app/verify.mjs --full` は未実行や依存不足をblockedとして扱い、成功終了しません。すべてのローカル試験に合格した将来の時点でも、第三者レビューや公開環境の運用条件を自動的に満たしたことにはなりません。
