# RealDEX v0.9 統合開発版 — 起動・DEX操作・復旧

2026-09-05 / 0.9.0-dev.20260905

## 最初に

本版は全チェーン対応の本番完成版ではありません。未監査の開発版です。実資産・普段使いの秘密鍵を入れないでください。ネットワーク候補の登録数と送信対応数は異なります。

新しい追加層は Node.js 22.16 以降で起動します。この作業環境で確認したのは Linux / Node 22.16.0 です。ルートの React/Hardhat 全体には package.json が固定する Node 24.14.0 と正規の依存パッケージが必要です。今回その全体ビルドは合格していません。

## 1. 一つのコマンドで起動

展開したフォルダーの `app/`・`wallet/`・`node/` が見える場所で実行します。

```sh
node app/cli.mjs start
```

依存を追加しなくても、ウォレットと読み取り専用の共有ノードを別プロセスで起動します。

- 共有ノード: `http://127.0.0.1:8787/node/`
- ウォレット: ターミナルに出る `http://127.0.0.1:8790/wallet/#key=...` の専用URL。

`#key=` を含むURLは所有者の操作権限です。AI・他のノード・第三者に渡さないでください。通常のノードURLとは区別します。パスワードやAI用トークンを、このURLの代わりに流用しません。

Ctrl+C で今回起動した二つのプロセスを停止します。起動に失敗しても、先に他のアプリが使っていたポートのプロセスは止めません。OS強制終了後のロックファイルは自動削除しません。

```sh
node app/cli.mjs start --directory /YOUR/PRIVATE/DIRECTORY --node-port 8787 --wallet-port 8790
node app/cli.mjs doctor
```

`start-realdex.sh`、`start-realdex.cmd` も同梱しています。Windows実機・Windows ACL・cmd起動は未検証です。既存ノード設定のポートを変更する際は、保存した `node/config.json` と指定値を一致させてください。

### 保存先と旧版からの扱い

新ランチャーの既定保存先は `~/.realdex-app/` です。その中の `node/` と `wallet/` を分離します。旧版の `~/.realdex-wallet/` は勝手にコピー・上書きしません。

旧保存先を使い続けるときは、従来どおり次で起動してください。

```sh
node wallet/cli.mjs start
```

移行する場合は旧プロセスを停止し、保存した暗号化バックアップとパスワードで、新しい空の保管庫へ復元します。新旧プロセスを同じ保管先で同時に動かさないでください。本版はBIP39の12/24単語復元ではありません。AI権限は復元だけで自動再開しません。

## 2. ウォレットの準備

画面で保管庫を作成し、試験用EVM口座を作成します。暗号化バックアップを保存し、そのファイルを読み戻して口座一致を確認します。この確認前は署名できません。

初期設定には送信先ネットワーク・契約・資金を登録しません。利用者が別に用意したテストEVMノード、実際のgenesis hash、2〜4個のRPCを指定します。URIが二つでも運営者や内部ノードが同じなら独立検証にはなりません。

内蔵署名器のチェーン制限は旧版のままです。任意の候補チェーン、メインネット、Base Sepolia等の未対応追加費用モデルへ昇格する機能ではありません。ICP/Solana/privacy系の送信も追加していません。

## 3. Factory・直接Pool・トークンを登録

「テストネットと契約許可リスト」のJSON読込では、既存と同じチェーンIDの設定を更新できます。対象は自分が検証したアドレス・runtime hash・トークン桁数・有限承認上限です。書式は `wallet/lib/network.mjs` の `validateNetwork` に従います。

同じチェーンIDでgenesisを変える置換は拒否します。既存設定の更新は、新旧設定・契約の追加／変更／削除を表示し、90秒以内の確認文入力を要求します。例: `REPLACE 31337 AND LOCK`。

適用すると、保管庫をロックし、既存のアプリ接続とAI接続権限を停止し、未署名の依頼を失効させます。進行中の署名・送信がある間は設定変更を拒否します。再解除後もAI権限は自動再開しません。確認文はコード監査や第三者証明の代わりではありません。

## 4. ウォレット画面のDEX操作

「プール作成・交換・流動性」で口座とネットワークを選び、「登録した契約を読み込む」を押します。読み込み自体はオンチェーン安全性の証明ではありません。

利用可能なフォームは、Factoryのプール作成、有限額のERC20承認、承認取消、直接Poolスワップ、流動性追加、流動性引出しです。数量は人が読む小数で入力し、署名サービス内で正確な整数へ変換します。

スワップは同じペアの登録済み直接Poolを比較できます。準備高・見積り式・コードハッシュ・トークン桁数をRPC上で照合します。ただし順位は追加ガス・承認費用を引く前です。分割・複数ホップ・ブリッジを含む実質最適ルートではありません。見積りを入力欄へ反映しても承認依頼・署名・送信は行いません。

必要な場合は先に有限額の承認を別操作として行い、次に交換を依頼してください。残高・既存承認が不足すれば停止します。各操作は「承認待ち」で受取先全体、金額、最低受取量、期限、ガス上限を確認します。所有者操作の「署名後に送信する」は既定で未選択です。

LP数量は既存LocalSwapPoolの18桁です。流動性追加は比率に応じて実際の引落額が上限未満になる場合があります。残る承認は別途取り消してください。

**作成したプールは自動登録しません。** 実際のアドレス・コードを検証してから設定を更新します。自分が配置したFactoryでも、候補情報やシミュレーション結果だけから送金先へ採用しません。

## 5. AIの送金前確認

v0.8の専用口座・受取先・数量・費用・期限・回数制限は維持します。MCP/SDKに読み取り専用の `realdex_agent_preview` を追加しました。

```js
// 既存の AgentWalletClient を、環境変数から読み込む接続トークンで初期化した後。
const request = {
  idempotencyKey: 'one-logical-invoice-001',
  recipient: 'OWNER_APPROVED_TEST_ADDRESS',
  amountAtomic: '1000',
};
const observed = await client.preview(request);
// preview は予算を予約しません。送信が必要な場合も、同じ論理支払いには同じキーを使います。
// await client.transfer(request);
```

上の受取先は置換が必要なプレースホルダーです。AIにはDEX操作、トークン承認、任意署名、ネットワーク変更、保管庫解除の権限を与えていません。所有者の無操作ロックをAIアクセスで延長しません。

模擬送金だけを確認するコマンド:

```sh
node wallet/agent/demo.mjs
```

このデモは一時保管庫と合成RPCを使います。チェーンへの送金試験ではありません。

## 6. 受取証の再照合

「署名・送信履歴」の再照合は、以前に成功表示になった取引にも使えます。取引本体と受取証を署名済みバイト列、ブロック、indexに結び付け、確認数と観測日時を表示します。

既定の確認数条件は12、finalityTagはnoneです。ネットワーク設定の任意項目で変更できます。

```json
"confirmationPolicy": {"minConfirmations": 12, "finalityTag": "none"}
```

これは「12なら安全」という保証ではありません。条件を満たしたかはRPCの報告であり、独立した最終性証明ではありません。safe/finalizedを指定してRPCが対応しない場合は、勝手に条件を弱めません。

受取証が消えた、別ブロックへ移った、RPC結果が一致しなくなった場合は、最新の成功・受取表示を更新または取り消します。履歴照合で自動再送・AI予算返却はしません。署名済み取引は、画面をロックしても無効化できません。

## 7. コンパイル済みPool照合の準備

この作業環境ではコンパイラを取得できていません。真正なbuild-infoや生成済みidentityを同梱したという意味ではありません。

信頼できる環境で同じソースと設定を実コンパイルして得たbuild-infoを使う場合:

```sh
node wallet/contracts.mjs build-identity --build-info PATH_TO_BUILD_INFO.json --output pool-identity.json
node wallet/contracts.mjs inspect --identity pool-identity.json --sha256 PRINTED_SHA256 --network network.json --request pool-request.json
```

requestは `factory`、`tokenA`、`tokenB`、整数 `feeBps` です。build-infoのソース一致、既存のローカルコードハッシュ、Pool初期化コード、immutable参照範囲を照合します。inspectは読み取りだけで、ウォレットへの登録も送信許可も行いません。

## 8. 試験と全体の合否

```sh
node app/verify.mjs --full --output acceptance-new
```

出力先は存在しない新しいディレクトリを使います。選択Node試験、依存診断、全体ビルド、既存契約試験、React試験、実EVM用追加試験を区別します。今回の環境では選択試験が通っても後半がblockedになるため、終了コード2になります。blockedを合格へ読み替えません。

正規の固定依存が揃った環境で、実EVM追加試験だけを実行するコマンド:

```sh
node node_modules/hardhat/internal/cli/cli.js test --config integration/hardhat-wallet.config.cjs
```

5件の実EVMシナリオを同梱していますが、本版作成時は未実行です。二つのHTTP入口は一つの実EVMへ転送する構成で、独立した二つの検証ノードではありません。本番・公開テストネットへの自動デプロイはありません。
