## 1. 再現した不具合と修正

### 1-A. ロック後に待機中の解除が成功する

旧版では `unlock()` の要求を出した直後に `lock()` を呼ぶと、解除コールバックが後から実行され、保管庫が解除状態に戻りました。旧版の再現結果は `pre-fix-queued-unlock.json` に記録しています。

原因は、操作の世代をキューへ入れる時点ではなく、実行を始める時点で取得していたことです。修正後は要求時に世代を固定し、実行までにロックが入った要求を拒否します。古い要求が新しい解除セッションへ入り込むことも拒否します。

HTTP側も、認証済みヘッダーから本文受信完了までの間にロックが入った古い要求を拒否します。実HTTPで本文を途中まで送信し、ロック／再解除後に残りを送る試験を追加しました。

### 1-B. 保存成功後に、容量のため解除できなくなる

旧版は書込み側の上限と、暗号文hexを読む側の上限が一致していませんでした。合成の有効な履歴を追加した試験では、902,654バイトの暗号化ファイルを保存できた一方、902,404文字のciphertextにより次の解除が `VAULT_CIPHERTEXT_INVALID` で失敗しました。

修正後は暗号化前450,000バイトで検査し、読取り側と一致させます。上限超過で元ファイルが読めるまま残ること、上限近くのファイルは再解除できることを確認しました。容量上限に達したとき、履歴や予算を黙って削除しません。既に壊れた旧版の読み取り状態を自動修復する移行ツールではありません。

## 2. 保存障害とロックファイル

write・ファイルfsync・rename前後・作成時link・初期lockのfsyncなどを故障注入で確認しました。一時ファイルの後処理を、renameだけでなくwrite/fsync/closeを含む範囲へ広げました。

置換前のエラーでは元ファイルを維持します。rename後のディレクトリfsync失敗は結果不確定なので、成功として返さずロックしますが、ディスク上の内容が旧版へ戻る保証はありません。

保存先ディレクトリとwriter.lockのdev/ino・所有者・非公開権限を確認します。自分のlockが削除・差替えされると保存を拒否し、終了時に他者のlockを削除しません。Unixで確認したもので、WindowsのACL・実機挙動を試験したわけではありません。

## 3. 共有ノードへの環境変数転送

一括起動から子ウォレット・子ノード・初期化へ渡す環境を許可リストに変更しました。AIトークン、署名鍵、クラウド鍵、NODE_OPTIONS、プロキシや公開RPCの環境変数を自動転送しません。別プロセスを実際に起動してsentinel値が渡らないことも確認しました。

同じOSユーザーの侵害や自由なファイル読取りに対する防御ではありません。独自認証ノードなど、これまで暗黙の環境引継ぎへ依存した構成は見直しが必要です。

## 4. 空の試験・省略した試験・途中変更を合格にしない

`app/verify.mjs` の選択試験は、終了コード0だけでは通りません。テスト件数が1以上、全件pass、fail/cancelled/skipped/todoが0を要求します。ゲートの欠落・重複・blocked・not-runも全体合格を妨げます。

対象ソース、試験、静的資産、固定依存設定等を実行前後にSHA-256で比較します。途中の開発用実行はソースを変更したため、1,456試験が成功してもソース整合性は不合格になりました。これは `preliminary-changing-source/` の記録で、配布候補の合格記録には使っていません。固定後の実行は1,458件成功・指紋一致です。

最終作業ツリーのソース指紋:

`8786d55f8855d533963e616c44ddf8f9c6ce4878d718b8acc7d208e7af47bc97`

この指紋は文書・過去証拠・生成物・依存インストール・秘密ファイルを除く限定スコープです。全配布ファイルは別に `FILES.sha256` で確認します。ハッシュは署名された独立リリース証明ではありません。

## 5. 固定コンパイラとCIの入口

公式Linux x86-64 Solidity 0.8.24のSHA-256を固定したローカル入口、standalone standard-JSONコンパイル、Hardhat用の明示的overrideを追加しました。欠落・サイズ違い・同サイズのハッシュ違いを拒否する経路は試験済みです。

ただし、公式コンパイラ本体を取得できておらず、**コンパイル成功経路・Pool identity生成の結合・実EVM実行は未実行です**。コンパイル済みの架空成果物は生成していません。

GitHub ActionsのworkflowはNode/pnpm・公式solc・隔離ブラウザを用意し全体判定を実行する定義です。checkout/setup-nodeを確認したコミットへ固定し、contents readのみ、資格情報をGitへ残さず、デプロイ・公開・本番秘密鍵を使いません。YAMLの構文を確認しましたが、GitHub上の実行は行っていません。
