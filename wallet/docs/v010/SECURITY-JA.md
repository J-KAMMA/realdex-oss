# RealDEX v0.10 — 本番前の安全性とリリース条件

2026-09-05 / 未監査・開発版。公開、デプロイ、実資産取引は行っていません。

## 今回修正した境界

### ロックは待機中の要求にも適用する

保管庫の操作は依頼時のロック世代に結び付けます。順番待ちの解除・書込み・署名は、実行時に世代が変わっていれば拒否します。待機上限は32操作です。HTTPヘッダー認証後に取得した世代も本文受信後に照合し、遅い本文をロック後の要求へ化けさせません。ロック・AI全停止・取消しの緊急操作はこの待機列に閉じ込めません。

ただし、既に外部へ送った署名や開始済み通信はロックで取り消せません。送信不明を失敗へ置き換えたり、自動で新取引を作り直したりしません。

### 読めない保管庫を新しく保存しない

暗号化前データ上限450,000バイトと、読取り時のciphertext hex上限900,000文字を一致させました。暗号化・保存エラーで保管庫をロックし、署名を呼出元へ成功として返しません。容量超過では直前の保存済みファイルが維持されます。

上限対策は自動的な履歴削除ではありません。容量に達すると追加操作が止まるので、容量監視・認証済みアーカイブは今後の課題です。以前の不整合で既に読めないファイルの自動修復は含みません。

### ファイル所有権と原子的な置換

読書きの前に保存先ディレクトリと保持するwriter.lockの識別を確認します。他のlockへ差し替わった場合は止め、終了時にも他者のlockを削除しません。Unixでは保存ディレクトリ・ファイルの所有者と非公開権限を再確認します。

一時ファイルのwrite・fsync・rename等のエラーを試験し、置換前の失敗では元ファイルを維持し、今回作った一時ファイルを後片付けします。**rename後にディレクトリ同期が失敗した場合は、旧状態への復元を保証しません。** 成功を返さず、保管庫をロックし、ディスク上の状態を再確認する必要があります。ディスク故障・悪意ある同一OSユーザー・永続化機構全体の保証ではありません。

### 子プロセスの環境変数

一括起動は許可した基本環境だけをウォレット・共有ノード・ノード初期化へ渡します。AIトークン、署名鍵、クラウド鍵、公開RPC URL、NODE_OPTIONS、プロキシ設定等は暗黙には引き継ぎません。

これは同じOSユーザーに対する強い隔離ではありません。任意のシェル・画面操作・ファイル読取りをAIへ許す場合、MCP権限だけを制限する構成とは保護条件が異なります。環境変数を渡さなくても、悪意ある子プロセスが同一ユーザーのファイルを読める問題は残ります。

## 合格判定

選択Node試験には、終了コード0だけでなく、テストが1件以上、全件pass、fail/cancelled/skipped/todoが0であることを要求します。必要なゲートが欠ける・重複する・一部blockedの場合に全体を合格としません。

実行前後のソース・試験・静的資産・主要ツール設定のSHA-256を比較します。履歴資料、文書、生成物、依存インストール、秘密データはこのソース指紋の対象外です。配布全ファイルの `FILES.sha256` は別の検査です。いずれも独立署名されたリリース証明や悪意ある実行環境に対する証明ではありません。

固定コンパイラはサイズ・SHA-256・権限を確認します。異なる実行物や欠落時に代替を探しません。ただし、同じユーザーが検証後にファイルやOSを改変できる状況への保護ではありません。ビルドホスト自体も隔離・信頼が必要です。

## 本番へ出す前に未達の条件

- 固定Node・依存・公式コンパイラを用意した全体ビルド、原契約全試験、実EVM統合、実ブラウザHTTP/CSPの成功。
- 対応する実テストネットのトランザクション、再編、手数料、受取数量・再送・復元の確認。
- 鍵保管、署名、ファイル保存、API境界、依存・更新配布に対する独立レビュー。OSの鍵保護とWindows実機検証。
- 古いバックアップによる履歴・nonce・予算巻戻し、複数端末での同じ鍵、署名済み取引の漏出への方針。
- 非EVM送信、秘密資産ウォレット、実ブリッジ決済・回復、分割Router等は機能自体が未達。

ローカル試験が全部成功しても `productionReady` を自動でtrueにしません。コードを書いた本人の試験と、独立監査・実環境での確認は別です。
