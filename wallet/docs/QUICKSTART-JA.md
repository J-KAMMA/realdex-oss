# RealDEX v0.7 ウォレット起動・復元・接続手順

作成日: 2026-09-05。対象: 本ZIPの `wallet/`。

## 目的と現在の範囲

共有ノードを動かしたまま、別のローカルサービスで自分の鍵・署名・承認を管理します。実資産を使わず、専用の試験用口座で確認してください。第三者監査、実チェーンの送信、ネイティブアプリ配布、Windows実機は未検証です。

EVM / ICP / Solanaの鍵生成・32バイト鍵取込・閲覧専用登録・暗号化保管・復元・自動ロックを利用できます。ICP/Solanaの画面からの送金、Monero等の秘密残高走査、全チェーンのスワップとブリッジ完成を意味しません。

## 1. 起動

ZIPを展開し、`wallet/` と `package.json` が見えるプロジェクトのルートで実行します。

```sh
node --version
node wallet/cli.mjs start
```

追加ウォレットはNode 22.16.0/Linuxで検証しました。ルートの既存React/Hardhat開発環境は別途Node 24.14.0 / pnpm等の指定を持ちます。ウォレット単独起動の要件と混同しないでください。

Linux/macOS向け `./start-wallet.sh` と、Windows向け `start-wallet.cmd` を同梱しています。Windows用はランチャーのソースを用意しただけで、実機・ACL・ブラウザ結合を確認したものではありません。

ターミナルに表示される **`http://127.0.0.1:8790/wallet/#key=...` の専用URL** を同じPCで開きます。末尾は画面操作権限です。他人・共有ノード・ログ収集サービスへ渡さないでください。ページは読み込むとURLの鍵部分を取り除き、メモリ内でのみ保持します。再読み込み後はターミナルの専用URLを開き直します。

既定の保管先は `~/.realdex-wallet`（ホームディレクトリ直下）です。リポジトリやOneDrive等の同期フォルダーには置かないでください。別の専用ディレクトリを使う場合だけ指定します。

```sh
node wallet/cli.mjs start --directory /absolute/private/wallet-test --port 8790
```

ポート変更時はプロバイダー側のbaseUrlも変更が必要です。ReactのPC Walletボタンは既定8790を使用します。`0.0.0.0`での公開やリバースプロキシ経由の鍵API公開はしないでください。

## 2. 作成・バックアップ

画面で十分に長く使い回していないパスワードを設定し、EVM / ICP / Solanaの試験口座を作成します。口座ごとに独立した鍵を生成します。32バイト秘密鍵/Ed25519 seedの取込もできますが、実資産のある鍵は使わないでください。画面上の入力以外にコマンド引数・環境変数・通常ログへ鍵を入れません。

**12/24単語のリカバリーフレーズ機能、BIP39、HD導出は未実装です。** 暗号化バックアップJSONとパスワードの両方を保管してください。試験コード内の鍵は公開テストベクトルであり、資産を送ってはいけません。

「暗号化バックアップ保存」でファイルを保存し、「保存したバックアップを照合」でそのファイルを読み戻してください。現在の口座集合と復元アドレスが一致するまで署名できません。口座追加・パスワード変更後は再バックアップが必要です。

パスワード変更は古いバックアップを無効化しません。古いバックアップは当時のパスワードで復元可能です。変更は秘密鍵のローテーションでもありません。

## 3. 復元とロック

既存保管庫を上書きしない設計です。復元試験は新しい空ディレクトリで起動し、暗号化JSONとパスワードを指定します。復元直後はロック状態です。解除後にアドレスを元口座と比較し、バックアップ照合を行ってください。

5分の無操作で自動ロックします。画面のロック、またはターミナルでCtrl+Cでも停止・ロックできます。共有ノードは別プロセスなので動かし続けられます。ブラウザを閉じた際の通知はbest-effortです。確実に止めるときはロック操作またはCtrl+Cを使います。

既にRPCへ送信した取引はロックで取り消せません。古いバックアップには直近の取引履歴がない場合があります。別端末復元後はチェーンを照合し、新規送信を急がないでください。

## 4. テストネット設定

初期状態ではRPCも契約も登録しません。「ネットワーク設定」で2〜4個のRPC、利用者が別経路で確認したgenesis hash、チェーンID、費用上限を入力します。独立したノードを推奨します。同じ運営者のURL二つを独立した検証とみなしてはいけません。

この版の設定で許すチェーンIDは `1337, 31337, 11155111, 17000, 97, 80002, 43113, 1001` です。このリストは本実装の制限であり、ネットワークの現在の稼働状況や全RPC互換性を検証した一覧ではありません。

本番IDや任意IDは拒否します。**Base Sepolia 84532、Arbitrum Sepolia 421614等のロールアップは追加費用計算が未実装なので拒否します。** 実装を変更してこの制限だけを外すことは勧めません。

RPCはHTTPS、またはループバックHTTPに限定します。認証情報・クエリを含むURLは拒否します。公開RPCへ自動フォールバックしません。EIP-1898のブロックハッシュ指定等に未対応のノードでは停止します。

設定JSONの各項目は `wallet/lib/network.mjs` の `validateNetwork` が定義します。`broadcastEnabled:false` は署名保存だけ、`true` は明示承認後の送信を許します。既存エントリーの上書きAPIはありません。設定変更はロック・停止してから行い、再起動時に検証します。

ERC20・Pool・Router・Factoryを使う場合は、実アドレスと実行コードハッシュを自分で検証して登録してください。token decimals・symbol・有限承認上限、Poolの両トークンも必要です。ZIPに実配備先・架空の配備先・信頼済みの公共プールは埋めていません。

## 5. 操作の確認と送信

ローカル画面ではEVMネイティブ通貨/登録ERC20の送金を準備できます。受取先、数量、トークンアドレス、チェーン、費用上限を見て、受取先の全文を入力して承認します。閲覧専用口座は署名に選べません。

接続したDEXからは、登録済み契約に対するトークン承認/取消、プール作成、直接/Router経由スワップ、流動性追加/引出しを受けられます。任意データをそのまま署名する機能ではありません。プール作成後のプールも自動で信頼済みにはなりません。

署名直前に残高、nonce、コード、最低受取、期限などを再照合します。署名とnonce予約を暗号化履歴へ保存してから送信します。接続取消・ロックは、まだ送信していない操作を停止します。通信を開始済みの取引は取り消せません。

送信結果不明は `broadcast-unknown` として残します。自動再送・nonceを変えた再試行はしません。履歴を照会した後、手動で取引ハッシュ全文を確認して、必要な場合だけ**同じ署名済みバイト列**を再送します。手数料引上げ、取消取引、nonce置換、履歴アーカイブは未実装です。RPCの成功報告と、コンセンサス上の不可逆な確定は別です。

## 6. 既存DEXとの接続

PC Walletボタンは**実験用 `src/App.tsx` / `/experimental.html`** にあります。既存フロントエンドの依存関係と開発サーバーが使える環境で、ルートREADMEの手順に従って起動してください。今回React全体のビルドや実ブラウザ結合までは確認していません。

ウォレットを先に起動・解除・バックアップ照合し、対象チェーンを設定します。ローカルDEXで「PC Wallet」を選び、通常の接続ボタンを押します。ウォレット画面に表示したorigin・口座・チェーンを確認し、別画面で接続を承認します。取引ごとに再度確認します。

既定の許可originは `http://127.0.0.1:8787`、`http://127.0.0.1:5173`、`http://localhost:5173`。これはアプリの接続元であって署名権ではありません。共有ノードに取引署名APIを追加したわけではありません。公開HTTPSサイトとのローカル接続は本版の対象外です。

**標準 `src/v01/V01App.tsx` は従来のMetaMask/Base Sepoliaの制限を維持**しています。未承認の配置記録を有効にしたり、標準画面の公開ゲートを解除したりしていません。

## 7. 再現試験

```sh
node wallet/test/run.mjs
node node/test/run-tests.mjs --with-release
node wallet/test/cli-smoke.mjs
```

追加53件、既存選択1171件です。プロジェクト全体の全テストではありません。実HTTPは合成RPCサーバーとの通信です。

追加の独立照合にはPythonのcryptographyが必要です。

```sh
node wallet/test/independent-vectors.mjs > /tmp/realdex-public-vectors.json
python wallet/test/independent-verify.py /tmp/realdex-public-vectors.json
```

出力する秘密値は公開テスト鍵のみです。独立96ケースの照合は実チェーンでの送信検証ではなく、EVMのKeccakダイジェストはJavaScriptから渡したものを検証に使います。

## 8. 困った場合

`VAULT_IN_USE_OR_STALE_LOCK`等で起動できないときは、同じディレクトリのプロセスが残っていないかOS側で確認してください。ロックファイルは自動削除しません。動作中に削除すると二重書込みの危険があります。

解除失敗・バックアップ破損・履歴容量超過は、保管庫を削除して解決しようとしないでください。先に暗号化ファイルを保全します。パスワードや鍵を問い合わせ用ログへ貼らないでください。
