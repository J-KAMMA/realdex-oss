# RealDEX Agent Wallet v0.8 — 権限境界と未解決リスク

**開発版／実資産禁止／独立監査未実施。** この文書は実装されたチェックと限界を区別します。テスト成功は資金安全性の証明ではありません。

## 強制する境界

AIの限定Bearerトークン、所有者UIの起動権限、既存dapp接続セッションは別物です。AIは所有者APIを利用できず、dappからAI権限を発行できません。秘密鍵はローカルの暗号化保管庫から外部AI・共有ノードへ出すAPIを持ちません。

AIのエンドポイントはloopbackのみで、Bearerと専用ヘッダーを要求し、Origin付きブラウザ要求やブラウザ由来のfetch-site等を拒否します。CORSを許可しません。ただしHTTPクライアントはヘッダーを偽装できるので、ヘッダー検査自体は認証の代わりではありません。実際の権限はランダムトークンと保管庫epoch・ポリシーの照合で検査します。

権限は所有者画面の2段階操作で発行します。口座、ネットワーク設定fingerprint、genesis、資産、受取先、期限、予算を固定します。AIによる任意raw calldata、承認操作、swap、bridge、署名・鍵出力、ポリシー変更は拒否します。

同じOS利用者を侵害した攻撃者、所有者画面そのもののXSS、デバッガ、改造されたバイナリ、管理者権限の攻撃はこの境界の外です。ローカル方針はオンチェーンのスマートアカウント制限やハードウェア財布と同等ではありません。OS鍵保管、ハードウェア保護、secure enclave、constant-time保証、メモリ消去の完全保証はありません。

## 予算と実際の残高

予約・署名済み依頼を整数で集計します。単発・直近24時間・累計・最大回数・間隔を検査し、署名前に最大ガスを予約します。署名時に署名履歴、nonce、依頼ID、使用額、ガス上限を1つの暗号化ファイルの原子的保存で確定します。書込失敗時はロックし、送信しません。

直近24時間枠は署名時刻と未署名予約で集計する枠です。署名済み取引が後日チェーンで実行された場合の、その日の実引落し上限を保証するものではありません。累計枠は署名済み全件を維持します。

予算は権限単位です。同じ口座へ複数の権限を与えるとそれぞれの上限が存在し、総許可額は増えます。口座全体・組織全体の包括予算ではありません。所有者による通常送金、外部で同じ鍵を利用した送金、過去のtoken allowance経由の引落しは、AI予算の対象ではありません。専用鍵・少額テスト資金を使ってください。

ERC20の予算はエンコードしたtransfer数量です。fee-on-transfer、rebase、proxy upgrade、悪意のあるtokenロジック、balanceOfの虚偽などから実際の引落し・受取量を一般に証明できません。runtime hashの一致はproxy背後のstorageや実装の永続性まで同定しません。trueを返す呼出し結果とTransferイベントの一致も、残高変化や最終性の証明ではありません。

EVM署名のリプレイ保護はチェーンIDに結び付いており、genesis hashそのものは署名形式に含まれません。ローカルのgenesis照合は送信先取り違えを防ぐ検査で、同じチェーンIDを再利用した別チェーンで、外部者が署名済み取引を再送することまで防ぐ暗号学的保証ではありません。私設チェーンを含めチェーンID・鍵の分離が必要です。根拠は REFERENCES.md のEIP-155を参照してください。

RPCの2〜4応答一致はコンセンサス証明ではありません。全接続先の共謀、同じ事業者、DNSやネットワークへの攻撃、実チェーンの再編に注意が必要です。価格オラクル、法定通貨換算、ガス実費の払戻し、追加L2費用は今回のAI予算機能にありません。

## 二重実行・競合・取消し

同一権限内でidempotencyKeyを固定し、内容hashの一致を検査します。予約は直列化し、同時依頼が残額を二重に使うことを防ぎます。同じ請求書をAIが別キーで申請した場合は、別支払いとして認識します。請求書同一性や支払理由の真偽は保証しません。

取消し・全停止はまずメモリの権限を消し、署名直前・送信直前に再確認します。ロック時に既存capabilityのepochを無効化します。ネットワーク送信を開始した後は取り消せません。署名済み取引は有効期限や権限取消しだけでは無効にならず、所有者が同一bytesを手動送信する経路は残ります。

署名済み／結果不明／revertedは予算から自動返却しません。未署名予約は期限が過ぎても予算に残し、所有者が明示取消しします。署名前の失敗だけ予約を解放します。タイムアウトで新しいキーへ自動再試行する機能はありません。

## 復元・時刻・容量

通常の再起動・解除で履歴と予算を保持します。AI活動は自動ロック時間を延長しません。再解除後の権限再有効化には所有者の明示操作とトークン再発行が必要です。バックアップを別の保管庫へ復元する場合は既存AI権限をすべて取消済みにして、古い残予算で自動再開しません。

古いバックアップには後から行われた取引履歴がありません。新しい権限を作れば新予算になるため、復元後の再付与は所有者が履歴と残高を照合する必要があります。改ざんしたシステム時刻を完全には防げません。稼働中の時計後退と永続保存済みlastSeenAtへの後退は拒否しますが、OSの時計を信頼する設計です。

上限はAI権限32、AI依頼512、全署名履歴1000。暗号化保管庫のサイズ上限が先に当たる場合があります。削除・予算リセット・アーカイブの自動化は実装せず、容量超過は停止します。AI側60req/分、並行読取・準備4件。所有者の停止・取消し・ロックの制御は通常のレート制限枠と分離します。

## 秘密情報とAIサービス

AIに同じOS利用者での任意シェル・ファイル読取・画面操作まで与える場合、そのAIが所有者URLやプロセス環境を取得して本APIの制限を迂回する危険があります。MCPの5ツールだけを与えることと、コーディングエージェントへPC全権を与えることは別です。本版はOSユーザー分離・サンドボックスを自動構築しません。

AIモデルはツール結果として、許可された口座、受取先、残高、金額、期限、依頼メモ、取引ハッシュを知り得ます。外部AIサービスで使う場合、そのサービスへの情報送信です。秘密鍵を渡さないことと、金融行動が非公開であることは別です。

AIが悪意のある文章を読んでも許可範囲外へは出られない設計ですが、許可範囲内で不必要な送金をする可能性は残ります。プロンプトインジェクションの経済的損害をゼロにする保証ではありません。既定の毎回承認、受取先固定、専用口座、低い上限を維持してください。

トークンは限定された送金権限なので秘密として扱います。環境変数、MCPホスト、クリップボード、デバッグログの保護は利用環境側にも依存します。画面で消してもコピーやスクリーンショットは取り消せません。stdio MCPのトークンはモデル引数に含めず、ローカルプロセスがHTTP認証へ添付します。
