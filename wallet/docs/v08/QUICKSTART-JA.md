# RealDEX Agent Wallet v0.8 — 起動・送金・AI接続

2026-09-05 / v0.8.0-dev.20260905

**開発・テスト専用です。実資産や普段使いの秘密鍵を入れないでください。** 内蔵送金は指定した一部EVMテスト／ローカルネットワークのみ。今回の実行確認は合成RPCで、実チェーン・実EVM・Windows実機・第三者監査は未確認です。

## 起動

ZIPを展開し、`wallet/` と `node/` が見えるディレクトリで実行します。

```sh
node wallet/cli.mjs start
```

Node 22.16.0以上。今回の検証環境はLinux / Node 22.16.0です。追加ウォレット部分の起動・Nodeテストにnpm installは不要です。React全体の開発環境とは別です。

ターミナルに表示される専用URLを**同じPC**のブラウザで開きます。`#key=` を含むURLは所有者画面の管理権限です。AI、他人、共有ノード、公開ログに渡さないでください。既定は `127.0.0.1:8790`、保管場所はホームの `.realdex-wallet`。別ディレクトリ・ポートは `--directory PATH --port PORT` で指定できます。

共有ノードを使う場合は、従来どおり別プロセスで起動します。ウォレットをロックしても共有ノードを止める必要はありません。

## v0.7からの更新

v0.7の保管庫は読み込める形式を維持しています。更新前に暗号化バックアップを保存してください。AI状態を保存したv0.8保管庫は、v0.7の厳格な旧スキーマでは読み込めないため、同じディレクトリで旧版へ戻さないでください。旧バックアップの保全と、新規ディレクトリでの復元確認を推奨します。

## 普通の送金

最初に新しいテスト用保管庫とEVM口座を作成し、暗号化バックアップを保存します。保存したファイルを再読込して、口座の一致を検証してください。新規口座追加後は再バックアップが必要です。BIP39/12・24単語方式ではなく、**バックアップファイル＋パスワード**で復元します。

ネットワーク欄へ、利用者自身が確認したチェーンID・genesis hash・異なる2〜4個のRPC URLを登録します。送信許可のチェックは初期状態でOFFです。第三者の設定や共有ノードのプール情報は自動信頼しません。自前チェーンの構築、RPC運営者の独立性、テスト通貨の用意は別途必要です。

署名を受け付けるIDは `1337, 31337, 11155111, 17000, 97, 80002, 43113, 1001`。これはコード上の許可IDで、各ネットワークの現在の稼働を確認済みという意味ではありません。メインネット、Base Sepolia等の未対応追加費用モデルは引き続き拒否します。

送金画面で口座・ネットワーク・資産・受取先・数量を選びます。数量は `0.001` のような十進文字列で入力し、署名サービスが最小単位へ変換します。指数、負数、超過桁数、ゼロ送金はこのUIで拒否します。EIP-55形式の大文字小文字混在アドレスはチェックサムも検査します。

「照合して確認画面へ」ではまだ送信しません。承認欄でチェーン・受取先・数量・ガス代上限を確認し、受取先全体を再入力します。自分の送金は署名だけに留めるか、明示的に送信するかを選べます。署名済み取引は後で第三者が送信し得るため、署名だけでも資金移動の権限を発生させます。

ERC20は手動設定した資産だけです。`contracts` の `kind: "erc20"` にアドレス・runtime hash・symbol・decimals・有限のapprovalCapAtomicを指定したネットワークJSONを読み込んでください。今回の送金は `transfer` であり、追加承認は不要です。コードハッシュ、桁数、残高、`eth_call` の戻り値を照合しますが、任意トークンの内部挙動や実際の受取量を証明するものではありません。

## 受取リクエスト

「受取リクエストを作成」で、選択中の口座・チェーン・資産のERC-681形式URIを表示します。QR生成やOSプロトコルハンドラーは未追加です。読み込めるのはチェーンID必須・hexアドレス・整数最小単位の限定サブセットです。ENS、指数形式、ガス指定、任意function、重複引数は受け付けません。

URIの読込は入力欄への反映だけです。作成者の正当性は証明されず、同じチェーンIDの私設チェーン同士をgenesisまで識別できるURIでもありません。送金前に相手・資産・ネットワークを別途確認してください。

## AI用ウォレット

画面の「AI専用のEVM口座を作成」で、主口座とは別の鍵を生成できます。新口座を保存・復元確認してから、AIの権限を作成してください。専用口座へ必要なテスト資金とガス代だけを用意します。既存口座も選択できますが、その口座の他の権限や操作までAI予算で制御するわけではありません。

権限は、1口座・1チェーン・1資産と、最大16受取先に固定します。複数資産を使う場合は別の権限を作ります。制限は権限単位で、複数権限の予算は別々です。全AI共通予算ではありません。

指定するのは、1回／直近24時間／累計の送金上限、同じ3区分のガス代上限、最大回数、最短間隔、有効期限（最大7日）です。ネイティブ通貨の送金では、送金額とガス代の両方が同じ残高から減るので、総負担は両上限の和です。ERC20上限は指定数量であり、法定通貨換算ではありません。

既定は**毎回本人承認**。最終確認欄に `REQUIRE MY APPROVAL` を入力して初めて権限を発行します。自動モードを明示選択した場合だけ、`ALLOW BOUNDED AUTOMATION` という別の文を入力して許可範囲内の自動送金を有効にできます。AI自身はモード・上限・受取先を変更できません。

発行される64桁の接続トークンは、AI用APIにだけ使います。画面では伏字で一度だけ提示し、60秒後・ロック・停止で消去します。コピー後のクリップボードやAIアプリの秘密情報保存先まで自動消去できるわけではありません。

**このトークンも機密情報です。** 秘密鍵とは別ですが、盗まれた場合は有効な間、許可範囲で操作されます。トークンをLLMのプロンプト・コード・公開設定へ貼らず、ローカルの秘密情報管理／環境変数 `REALDEX_AGENT_TOKEN` に保存してください。所有者URLやウォレットパスワードは絶対に代わりに渡しません。

「すべてのAIを停止」は画面が別処理を待っている間も利用できます。個別の取消しも可能です。5分の所有者無操作でロックし、AIによる読取・送金はこの時間を延長しません。再解除・再起動後は自動で再有効化されず、所有者の確認と新トークン発行が必要です。旧トークンは無効になります。**常時無人で何日も動かす構成ではありません。**

## MCP接続

ローカルでstdio MCPサーバーを起動できるAIクライアントへ、次のコマンドを登録します。

```text
command: node
args: ["/展開先の絶対パス/wallet/agent/mcp.mjs"]
```

そのプロセスに `REALDEX_AGENT_TOKEN` を安全に継承させます。ポートを変えたときだけ `REALDEX_WALLET_URL=http://127.0.0.1:PORT` も設定します。URLは127.0.0.1のHTTP originに限定され、インターネットへ公開するAPIではありません。クラウド上のAIサーバーから利用者PCのlocalhostへ直接接続できる仕組みではありません。

`wallet/examples/mcp-config.example.json` は汎用設定例です。実際のクライアントの設定方法や環境変数継承方式は各クライアント側に従ってください。実トークンを書いた設定をGitへ登録しないでください。今回、特定の商用AIクライアントやモデルとの結合試験はしていません。

公開するMCPツールは以下の5つだけです。

| ツール | 動作 |
|---|---|
| realdex_agent_status | 当該権限、口座、予算消費、期限の確認 |
| realdex_agent_balance | 当該資産とガス用残高のRPC照合 |
| realdex_agent_transfer | 許可された受取先への限定送金依頼 |
| realdex_agent_result | 元の依頼キーで状態を確認。refresh=trueなら受取証の読み取り照合 |
| realdex_agent_history | 当該権限の送金依頼履歴 |

署名、鍵出力、解除、上限変更、任意コントラクト、approve、swap、bridge、シェル実行のMCPツールはありません。MCPツールの説明・annotationsは権限境界ではなく、署名サービスが別途すべて検査します。MCPプロトコルは2025-11-25と2025-06-18のstdioサブセットです。

## JavaScript SDK

`wallet/agent/client.mjs` と型宣言を同梱しています。環境変数から限定トークンを取得し、まずstatusで資産・桁数・受取先を確認します。

```js
import {AgentWalletClient} from './wallet/agent/client.mjs';
const wallet = new AgentWalletClient({
  token: process.env.REALDEX_AGENT_TOKEN,
  url: process.env.REALDEX_WALLET_URL ?? 'http://127.0.0.1:8790',
});
try {
  const status = await wallet.status();
  // amountAtomicは最小単位。下の値を通貨単位や円の値だと思わないこと。
  // 実際の受取先・数量は、所有者が承認したテスト支払についてのみ指定する。
  const request = {
    idempotencyKey: 'test-invoice-20260905-001',
    recipient: status.policy.recipients[0],
    amountAtomic: '1',
  };
  console.log(await wallet.transfer(request));
  console.log(await wallet.result(request.idempotencyKey, {refresh:true}));
} finally { wallet.destroy(); }
```

この例は明示実行すると1最小単位の送金を依頼します。実行方式がautoなら範囲内で送信します。既定が読取専用のCLI例は `node wallet/examples/agent-transfer.mjs` です。

## 結果不明・再送・復元

`idempotencyKey` は「同じ請求・同じ支払い」に対して固定してください。同じキーで同じ内容を再依頼しても署名・送信を増やさず、内容が異なれば拒否します。違うキーを使えば別の支払いとして扱うため、AIが業務上同じ支払いかを自動判定するものではありません。

タイムアウト、not-found、broadcast-unknownは失敗確定ではありません。元のキーで `result` を確認してください。`refresh:true` は署名も再送もせず、指定RPCから受取証を照合します。成功報告やTransferイベントだけでは、実残高変化・最終性を証明できません。

署名済み、結果不明、チェーン上で失敗した取引の送金額・ガス上限は、予算から自動で返却しません。未署名予約だけ所有者が明示取消しできます。再送は所有者の通常履歴画面から、同一署名済みバイト列だけです。**権限を取り消しても署名済み取引を無効化できず、所有者自身はそれを再送できる**ことに注意してください。

バックアップ復元時は、保存されていたAI権限をすべて取消済みにします。通常の同じ保管庫の再起動では予算消費を維持しますが、古いバックアップには後の履歴は存在しません。復元後、安易に新予算を与えず、後発の送金・nonce・残高を確認してください。

## オフライン動作確認

以下のデモは、一時ディレクトリの公開テスト鍵と合成RPCだけを使用し、終了時に削除します。普段の保管庫を開かず、実チェーンへ接続しません。

```sh
node wallet/agent/demo.mjs
node wallet/test/run.mjs
node node/test/run-tests.mjs --with-release
```

Node試験には追加パッケージ取得不要です。独立照合はPython cryptography、画面のオフライン試験はPlaywrightとChromiumが別途必要です。試験用鍵は公開済みfixtureであり、絶対に実資産を送らないでください。
