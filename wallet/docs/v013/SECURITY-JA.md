# v0.13 セキュリティ境界

本番使用・実資産の投入は未承認です。今回の変更は非EVMの制限付き開発経路であり、第三者監査ではありません。

## 鍵と権限

新しい署名APIは所有者専用です。AI、外部アプリ、共有ノードへ非EVM送金・任意署名・鍵出力権限を付与していません。ネットワーク設定変更は所有者の確認とロックを伴います。ロック前に始まった要求は既存のHTTP世代チェックと署名境界の再検査を通り、後から新しい解除セッションへ復活しません。既にネットワークへ渡した署名を取り消す機能ではありません。

OS同一利用者の侵害、メモリ読み取り、ファイル編集、capabilityやパスワード流出、バックアップのオフライン解析は、この層だけでは防げません。秘密バイト列を可能な箇所でクリアしますが、JS文字列やランタイムの複製の完全消去は保証しません。

## SOLの実装上の限定

System Programの単一ネイティブ送金、legacyメッセージ、署名1個、固定3口座、空データの通常送金元に限定します。任意instruction、SPL、Token-2022、アカウント初期化、durable nonce、versioned transaction、手数料優先命令、DEX、ブリッジは受け付けません。

ローカルRPCのgenesis一致は合意証明ではありません。2～4URLは独立運営や独立ノードを保証しません。`minContextSlot`も固定snapshotではありません。RPC値の不一致、安全整数超過、想定外の口座、シミュレーションの差分不一致は停止します。

署名のchain ID束縛はありません。genesisと設定fingerprintはRealDEXの保存・検査規則であり、オンチェーンの別ネットワークへの再生防止を保証する仕組みではありません。ローカルRPCが実ネットへ中継されていないことをコードから証明していません。開発専用の無価値な鍵を使ってください。

送金額と手数料を検査しますが、任意の相手先・外部ノードが示す状態の真正性までは保証しません。RPCの成功やfinalized表示を暗号学的証明として扱わず、保存したバイト列・実行前後残高の整合と併せて観測として表示します。

## 二重送信と保存

署名は暗号化記録への保存が成功してから返します。送信開始の不確定状態を先に永続化してからRPCへ署名を渡します。RPC応答消失は失敗と断定せず、結果不明に保持します。

同じ支払いキーの再署名と内容変更を拒否し、同一口座・ネットワークの未解決記録が残る間は別の署名も拒否します。新しいキーが同じ現実の請求書を表しているかを意味的に判定するものではありません。サービス外で支払われた取引の照合、複数端末・バックアップ巻き戻しへの完全な対策は未実装です。

署名済み取引の初回送信は手動でできます。送信済み／結果不明の再送、blockhashの更新、署名の置換、未解決記録の自動削除はありません。期限切れで支払いが未解決のまま止まる可能性は、保守的な既知制限です。

## ICP

署名付きICRC-1要求を所有者確認の後に保存するだけです。台帳のコード・残高・手数料を真正性込みで照合しません。root keyの信頼検査、BLS証明書、delegation、read_state、ingress結果、台帳の重複排除動作、実ICP決済は未検証です。

同じキーは同じ保存済み要求を返しますが、ネットワークや台帳がその要求をどう実行するかを保証しません。ローカル識別名は暗号学的なネットワーク束縛ではありません。canister IDと有効な鍵が別環境で意味を持つ可能性があるので、署名済み要求を一般の共有候補として配信しないでください。

## 互換性と未達

新フィールドを含む保管庫は旧バイナリで復号検査が通りません。旧バックアップへ戻すことによる履歴巻き戻しは安全な復旧策ではありません。容量上限を越えたときも、重複防止記録を消して続行しません。

ローカルLiteSVM試験は実行と署名の整合を見るものです。RPC/finality/genesisは試験用の合成値で、validatorや分散合意ではありません。合成APIの画面試験はブラウザHTTP/CSP結合の代用ではありません。Windows、OS保護、公開クラスタ、独立監査、正式EVMコンパイラと全React依存は別の完成条件です。
