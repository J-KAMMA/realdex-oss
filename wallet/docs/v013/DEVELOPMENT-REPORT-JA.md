# RealDEX v0.13 — 非EVMウォレット実装・検証報告

## 基準と変更の目的

基準は、実際に取得できたv0.12 `RealDEX-AMM-Route-Preview-2026-09-05.zip` です。入力ZIPのSHA-256は `d3ca2078f12f6ed4626b55d84a282ab109f0c3424121ee67dd071d651f8d87a2`。過去のメッセージの版名や件数だけを使わず、このZIPから変更しました。

今回の目的は、EVMだけでなく非EVMにも、所有者確認・署名・保存・送信後の再照合を追加することです。全非EVMチェーンの交換や全資産送信を実装したものではありません。

## 今回使える経路

| 対象 | 今回の到達点 |
|---|---|
| Solana | ネイティブSOLの通常口座間送金。ローカルRPC限定。準備、残高・手数料・署名期限・シミュレーション照合、所有者確認、署名、暗号化保存、初回送信、履歴再照合 |
| ICP | ICRC-1の署名済み支払い要求をオフライン作成・確認・永続化・復元・出力。canister、caller、subaccount、数量、手数料、memo、時刻を束縛 |
| AI／接続アプリ | 今回の非EVM署名・送信権限は提供しない。既存のEVM限定AI送金・予算検査は維持 |
| 共有ノード | 秘密鍵や新しい署名APIを持たせない。今回node本体は変更していない |

Solanaの対応範囲は単一System Program送金、legacyメッセージ、1署名です。SPL／Token-2022／任意instruction／durable nonce／優先手数料／DEX／bridgeには対応しません。ICPもネットワーク送信・read_stateの証明書検証・決済完了判定・Pool canisterを追加したわけではありません。

## 署名と保存

EVMの既存journalに別形式を混ぜず、暗号化保管庫へ任意の `nonEvmJournal` を追加しました。最大128件です。実行前にバックアップの口座一致を要求し、署名が保存されるまでネットワークへ出しません。入力した数量を正確な最小単位へ変換する処理はサービス側です。

同一口座・ネットワーク・支払いキーは以前の記録を返し、内容の変更は拒否します。送信応答を失っても、blockhash・memo・created_at_timeを変更した新しい支払いを自動生成しません。未知の状態を失敗と断定せず、Solanaの未解決記録がある間は同じ口座・ネットワークの新しい署名を止めます。

Solanaの署名だけを保存した記録は、署名ID全文の再入力によって初回送信できます。送信済み・結果不明の再送APIはありません。初回送信直前に署名の期限・手数料も再検査します。

## 実行環境での検証

Solders 0.29.0に含まれるLiteSVMを使い、実際のEd25519署名検証・System Program処理・残高変化を試験しました。テスト用wheelはアーカイブ・wheel・パッケージ42ファイルをハッシュ照合し、一時フォルダーから読み込みます。通常アプリの実行時依存にはしません。

重要な限定: **LiteSVMはin-processの実行環境であり、Agave validatorではありません。** JSON-RPC facadeのgenesis、slot、height、finalityメタデータは合成です。二つのURLの背後も一つのLiteSVMです。分散合意・公開クラスタ・独立RPC運営者を試験したものではありません。

送金例の実行では、1,000,000 lamportsの支払いに対し、受取口座が1,000,000から2,000,000に増加し、送信元が1,000,000,000から998,995,000へ減少しました。手数料5,000 lamportsとの整合を照合しています。これは無価値なローカル試験残高です。

LiteSVMの14シナリオは、未署名シミュレーション、所有者HTTP承認、実残高と手数料、同一依頼の二重処理拒否、受理後の応答喪失、未確定の非成功表示、観測消失時の成功撤回、blockhash失効、残高変更、genesis不一致、署名のみからの明示送信、初回送信前の手数料変更、ロック／再解除、暗号化バックアップ復元、所有者トークン境界を扱います。一つのシナリオに複数の確認項目を含むため、項目数を試験件数へ足し直していません。

## 未達・試行した環境制限

この環境はLinux、Node 22.16.0、Python 3.13.5です。正式のルートNode固定値は24.20.0で、この版のルート依存も未配置です。`npm run build` はReact、ethers、Viteなどの依存不足で失敗しました。npmレジストリへのcurlはDNSエラーでした。

通常ブラウザのローカルHTTP接続は `BROWSER_POLICY_BLOCK` で遮断されました。バックエンドがno-storeとCSPヘッダー付きHTMLを返すところは確認しましたが、実ブラウザ結合合格にはしていません。検査制限をオフライン画面の成功で置き換えません。

正式0.8.24コンパイラ、全ルートテスト、実ブラウザ結合、公開Solanaクラスタ／validator、ICPレプリカと認証済み決済、その他非EVM送信、全チェーン交換・ブリッジ、Windows実機、OSの鍵保護、独立監査は未達です。所有者用URLと鍵保管をOSサンドボックスで保護した版でもありません。

## 保全と互換性

既存の `contracts/`、`src/`、`node/`、ルートpackage.json・pnpm-lock.yamlは変更していません。walletの署名・保存・設定・所有者HTTP・画面と、appの版表示・試験ゲートは変更しています。入力ZIP全体の単なる追記ではありません。差分とハッシュ一覧を別添します。

非EVM記録を保存した保管庫は旧バイナリで読めません。保存元設定とfingerprintが一致しない通信先へ、以前の署名を送信することも拒否します。移行、未解決履歴解除、安全なアーカイブ、バックアップ巻き戻し対策は未完成です。

**本番利用判定はfalse、公開配置と実資産利用は実施していません。** 新しい対応件数や試験成功を、全チェーン・全トークンの本番適合性として扱わないでください。
